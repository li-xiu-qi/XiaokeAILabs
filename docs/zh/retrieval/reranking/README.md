# 重排序模型体系（Reranking）

> 阅读导航：[检索与排序](../README.md) · [单向量检索（Embedding）](../embedding/README.md) · [多向量晚期交互（ColBERT）](../colbert/README.md) · [知识蒸馏与软标签监督](../知识蒸馏与软标签监督.md)

在两阶段现代检索架构中，重排序模型（Reranker）承担第二阶段的高精度精排职责。在第一阶段由单向量模型（Embedding）或稀疏倒排索引（BM25）从海量全库中快速筛选出前 30 到 100 个候选后，重排序模型对这些候选执行**逐对全注意力深度交互计算**，将最相关的结果排在最前列（Top-1 到 Top-5）。

与粗召回阶段的双塔解耦架构不同，重排序模型普遍采用**交叉编码器（Cross-Encoder）**架构：将查询（Query）与候选文档（Document）拼接后送入同一个网络，在多层自注意力中进行双向词级交叉交互（Cross-Attention）。

## 二、双编码器 vs 交叉编码器结构与计算对比

| 特征维度 | 双编码器粗召回（Bi-Encoder / Embedding） | 交叉编码器精排（Cross-Encoder / Reranker） |
|---|---|---|
| **输入形式** | Query 与 Document **分开单独输入**两个塔 | Query 与 Document **拼成单一序列** `[CLS] Q [SEP] D [SEP]` |
| **词间交互深度** | **完全隔离**：词与词之间无跨文本注意力交互 | **充分交互**：每一层 Transformer 都在做全双向 Cross-Attention |
| **离线建库** | **支持**：文档向量可提前全量预计算并持久化 | **不支持**：必须在线对每个候选动态计算 |
| **单次计算复杂度** | $\mathcal{O}(L_q^2 + L_d^2)$（离线），在线仅 $\mathcal{O}(\log N)$ | $\mathcal{O}(K \times (L_q + L_d)^2)$，随候选数 $K$ 线性增长 |
| **典型输出形态** | 固定维度的连续稠密向量 $\mathbb{R}^D$ | 单一标量相似度分数 $\in [0, 1]$ 或实数 Logit |
| **系统分工定位** | 从千万级全库中快速筛选出候选池（召回） | 从数十个高价值候选中排定最终顺序（精排） |

## 三、系统边界与设计原则

1. **重排序无法找回未召回的文档**：
   重排序的评价指标主要是 **nDCG@k 与 MRR@k**。如果第一阶段的粗召回未能将真实相关文档纳入候选池，后端的重排序模型无论参数容量多大，都无法在候选池之外凭空找回遗漏文档。优化检索系统时，必须首先保证第一阶段的召回率（Recall@k）；
2. **严格控制输入候选数量**：
   在线生产部署时，送入重排序模型的候选数量通常控制在 **20 到 50 个之间**。过多候选会导致单次请求推理延迟超过服务 SLA 阈值，过少候选则会削弱重排序的筛选价值。
