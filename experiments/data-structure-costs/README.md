# 数据结构与存储格式的成本

[English](README.en.md)

为什么布隆过滤器能减少无效查询，代价又是什么？为什么同一份数据保存为 JSON、电子表格或数据库文件时，体积和读取方式会不同？本目录用简化成本模型和小规模脚本探索数据结构、索引与数据格式的空间及计算开销，帮助读者选择值得在实际工作负载上测量的问题。

这些脚本大多是教学模型或自制实现，不等价于数据库产品的实现。公式、机器环境、数据分布与具体实现都会影响结果；这里的理论数字不能直接用于预测生产系统的延迟。部分历史记录缺少原始结果和完整环境，不能作为可独立核验的性能结论。

## 从布隆过滤器开始

布隆过滤器把元素映射到位数组。查询得到否定时元素一定未被插入；得到肯定时仍可能是假阳性。位数组越大通常能降低假阳性，但需要更多空间。下面的示例用相同哈希方式和给定数据对比理论值与实测值；它测的是自制 Python 实现的假阳性率，不是数据库的查询延迟。

```bash
cd experiments/data-structure-costs
python scripts/bloom_filter_model.py
mkdir -p results
python scripts/verify_bloom_filter.py
```

这两个脚本只依赖 Python 标准库。验证脚本把本次生成的 JSON 写入 `results/`；该目录被 Git 忽略，仓库不附带这些运行结果。Windows PowerShell 中可以用 `New-Item -ItemType Directory -Force results` 创建目录。脚本中的理论值依赖近似及哈希假设，有限查询次数也会带来抽样误差。

向量索引已有独立实验，包含 Flat、IVF、HNSW 和量化的检索路径，以及注明条件的召回和耗时对照，请从[向量索引成本](../vector-index-costs/README.md)进入。本目录中同主题的历史脚本与文档仅供追溯，不作为新的向量索引实验入口。
