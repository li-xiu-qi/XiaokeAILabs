# Jev 系列实验报告

Jev 是 TypeSafe 推出的决策模型，面向预设题型输出概率。这篇报告在同一台机器上测试 Laya、Nimble、metask-jev 和生成式基线；其中 Nimble 使用另一组题目，其准确率不能与其他模型同表比较。

复现步骤看《复现教程.md》，每个数字的原始输出在 `docs/执行日志/`，下面每张表都标了出处。四个模型的实测结论和选型建议在报告末尾「怎么选」一节。

## 测了哪些模型

| 对象 | 形态 | 参数 | 底座 |
|---|---|---|---|
| Laya 1.1B | 双 checkpoint 自动分流 | 1.1B | ModernBERT |
| Nimble 9B | 单模型 | 9B | Qwen3.5-9B 加 LoRA |
| metask-jev-4B | 单模型 | 4B | Qwen3.5-4B |
| Qwen3-VL-4B | 生成式对照 | 4B | Qwen3-VL |

Laya、metask、Qwen 跑的是同一套题，20 条分类加 5 条命题判断。Nimble 的基准是另一组演示题，问的是工单优先级和是否需要人工复核两个字段，所以它的准确率不进表，只进延迟表。

测试输入固定，英文是一条 86 字符的重复扣费投诉，中文是它的对应翻译约 25 字。metask 的 prompt 拆成 token 后是 239 到 244 个。

## 延迟，全部取中位数

单位毫秒，同一台 aarch64 GB10，2026 年 9 月 22 日实测。

| 对象 | 输入 | 完整一次判定 | 常驻显存 |
|---|---|---|---|
| Laya 英文 checkpoint | 英文 1 题 | 16.98 | 5.96 GB |
| Laya 多语言 checkpoint | 中文 1 题 | 8.25 | 5.96 GB |
| Nimble 9B | 英文 2 字段 | 365.33 | 17.57 GB |
| Nimble 9B | 中文 2 字段 | 366.66 | 17.57 GB |
| metask-jev-4B | 英文 1 题 | 133.5 | 8.58 GB |
| metask-jev-4B | 中文 1 题 | 133.7 | 8.58 GB |
| Qwen3-VL-4B 最简输出 | 英文 | 103.48 | 8.30 GB |
| Qwen3-VL-4B 最简输出 | 中文 | 104.85 | 8.30 GB |
| Qwen3-VL-4B JSON 输出 | 英文 | 1448.17 | 8.30 GB |
| Qwen3-VL-4B JSON 输出 | 中文 | 1153.54 | 8.30 GB |

出处是 `docs/执行日志/` 下编号 02、04、05、07、08 五份日志。

Laya 英文比中文慢一倍。本次中英文输入经 Router 落到不同 checkpoint，且输入内容不同；测试无法隔离模型规模、输入与其他因素各自对延迟的贡献。

题数合并。一次请求塞 16 道题，总时长 45.32 ms，摊到单题 2.83 ms，只有单独调用的六分之一。冷启动方面，单 checkpoint 加载 23.21 s，三个 checkpoint 全部常驻 60.34 s，之后路由本身的判定开销是 0.02 ms 到 0.19 ms，可以直接当它不存在。

## 准确率，20 条分类题

| 对象 | 英文 | 中文 |
|---|---|---|
| Laya | 95.0% | 95.0% |
| metask-jev-4B | 95.0% | 100% |
| Nimble | 未测 | 未测 |
| Qwen3-VL-4B | 未测 | 未测 |

出处是 `docs/执行日志/` 下编号 03 和 07 两份日志。

Laya 中文错的那条：它把一条该归「其他」的消息判成了账单问题，置信度 0.906。高置信度的错误比低置信度的错误更难防，调用方如果按置信度设闸，这一条会直接漏过去。

## 三个结构性发现

三个威胁退订的中文句子中，Laya 给出的「命题为真」概率分别是 0.025、0.051、0.028，均判成假；对应英文例子三条均判对。这提示需要检查中文命题任务，但三个例子不足以判断整个中文判断能力。

同一批中文分类题使用英文 checkpoint 时，一致率为 75%，平均置信度 0.384。这些例子显示两种配置的结果不同，是否需要路由仍须在目标数据上比较。

本次题数合并测试展示了 Laya 的成本变化。1 题 16.87 ms，2 题单题 9.22 ms，4 题单题 5.61 ms，8 题单题 3.67 ms，16 题单题 2.83 ms。合并的边际成本在快速下降，因为一次前向就把所有题一起算完了。生成式模型也可以批处理；本次测试只能说明 Laya 在所测配置下合并题目的表现。

生成式模型的成本跟着输出长度走。Qwen3-VL-4B 的单次前向是 49 到 52 ms，和 Laya 的 17 ms 在同一个量级。可一旦要求它输出一个 JSON 对象，它要多生成 23 到 29 个 token，完整一次判定就从约 105 ms 涨到约 1150 至 1450 ms。Laya 不需要逐 token 生成答案，但耗时仍可能随题目与输入规模变化。这不是快慢问题，是成本结构问题。

## 测量口径

全部数字测于一台 aarch64 GB10、20 核 CPU、121 GB 统一内存、单卡 CUDA，时间 2026 年 9 月 22 日。工具是四个子目录里的脚本，样本量与预热方式逐项记在对应日志里。

输入是固定的两条短样本，英文一条 86 字符的重复扣费投诉，中文是它的对应翻译约 25 字，metask 的 prompt 拆成 token 后 239 到 244 个。输入长度可能影响耗时，具体关系需按目标负载实测。要做容量规划，用自己的真实输入重测一遍。

分类题 20 条，命题判断 5 条。这些短样本可以为本次配置提供初步线索，但不足以支撑普遍选型或业务准确率结论。Laya 中文 95% 与 metask 中文 100% 之间的差距不在本报告的结论范围内，`laya-zh-en.py` 自己也标了这条口径。

Qwen3-VL-4B 那组是在没有推理加速框架的情况下测的，属原生下界。推理引擎和部署配置可能改变结果，需要在相同负载下另测。

## 上游基准数据的取舍说明

metask 上游文档中列出了校准误差由 0.114 降至 0.040、JevBench 理论排名第一以及每千次决策 0.0029 美元等指标。在实际业务工单的实机测试中，上游的数据我们并未复现；且上游自述该榜单排名属于自测插值，未提交官方评测验证。

因此本报告在选型与对比中未采纳上述理论数字，全部指标均严格基于本地实机运行产生的日志记录（如 metask 方案端到端中位数延迟 133.7 ms 及中文场景 20/20 准确率）。

## 怎么选

在本次短样本配置中，Laya 的延迟和显存占用较低。8 到 17 ms，6 GB 显存，题数合并能把单题压到 2.83 ms。前提是场景不涉及中文的命题真假判断。

若考虑中文分类，可以将 metask-jev-4B 纳入候选。133.7 ms 不算最快，但它中文 20 条全对，8.6 GB 显存，模型卡自带各题型的温度系数，仍需在目标任务上用足量标注数据验证。

Nimble 9B 在此次测试中的资源占用较高。CUDA 路径上每个字段都要单独跑一次完整前向，上游 README 写得很清楚，Mac 上是共享一次前向后并行打分，CUDA 上不是。两个字段 365 ms，字段加到十个就是另一回事，加上 17.57 GB 的常驻显存是四条路线里最高的。本次任务和输入不同，不能据此判定其业务性价比。

Qwen3-VL-4B 不是候选，是对照。有它做尺子，判别式模型的优势才说得清：不在绝对速度，在成本结构。判别式输出可以避免逐 token 生成，但字段数、输入长度和并发仍会影响性能；是否适合实际决策路径需要按目标负载测试。
