# Train Your Own Vision Jev (Multimodal Decision Model)

[中文说明](README.md)

> **Historical results do not establish independent visual question-answering ability:** the old data included the reference-answer reasoning in `solution` as model input. Data preparation now removes this field, and a small 100-step run and test have completed; the originally planned full training remains outstanding. Do not use the old data or old weights for a new experiment.

`agent-jev-text` follows a text-only approach. This directory moves the same discriminative decision model to vision: it uses a multimodal backbone that can process images, and scores each candidate from the image, context, and candidate text together. A score head produces one scalar per candidate, which is then normalized across the candidates for that question.

There is no open-source training implementation on the model side to reuse: AgentJev is text-only, and Jev-Omni's training weights are not open source. This is a custom implementation. Its architectural organization is informed by `pngwn/system-one-qwen3.5-4b-scorer` (LoRA plus a scalar score head, per-question normalization, and temperature calibration), while the data, protocol, and training scripts are independently implemented.

## Components

| Item | Value | Notes |
|---|---|---|
| Backbone | Qwen3.5-2B | Apache 2.0, natively multimodal, about 4 GB of weights |
| Dataset | ScienceQA | Not gated, images embedded in Parquet; see licensing note below |
| Parameter-efficient fine-tuning | LoRA r=16 | This experiment uses LoRA; whether full-parameter training is feasible depends on the model, batch size, precision, and other settings |
| Loss | Soft cross-entropy + 0.1 × sum-candidate Brier | Same as the text version |
| Calibration | One scalar temperature, 81-point grid | Fit only on the calibration set |

The backbone can also be Qwen3.5-0.8B (1.7 GB of weights) or 4B (8.8 GB). Change `download_backbone.py --size` and `protocol.json` accordingly.

## Directory structure

```text
vision-decision/
├── scripts/
│   ├── download_backbone.py   # Download a Qwen3.5 multimodal backbone

```

## Environment setup

The historical training workflow requires Linux, a CUDA GPU, and an environment that supports bfloat16. The training script checks system memory through `/proc/meminfo`. Required GPU and system memory vary with the model, batch size, and precision; weight size alone is not enough to estimate them.

Create a dedicated Python virtual environment in this directory and install CUDA-compatible PyTorch and torchvision for the device. The example below uses PyTorch 2.14.0 / torchvision 0.29.0 with CUDA 13.0 from the [official PyTorch version table](https://pytorch.org/get-started/previous-versions/). First confirm that compatible wheels exist for the system architecture, driver, Python version, and GPU. This fresh environment has not been fully verified:

```bash
python3 -m venv .venv
source .venv/bin/activate
# CUDA 13.0 example; choose a matching combination from the official version table for other platforms
python -m pip install torch==2.14.0 torchvision==0.29.0 --index-url https://download.pytorch.org/whl/cu130
python -m pip install -r requirements.txt 'torch==2.14.0' 'torchvision==0.29.0'
python -m pip check
python -c "import torch, torchvision, pyarrow, peft; from transformers import AutoProcessor, Qwen3_5ForSequenceClassification; print('torch:', torch.__version__, 'torchvision:', torchvision.__version__, 'CUDA:', torch.cuda.is_available()); assert torch.cuda.is_available() and torch.cuda.is_bf16_supported()"
```

`requirements.txt` specifies minimum versions rather than a complete lockfile. It declares PyTorch; if a specific CUDA build is needed, choose and install the matching version for the device first, then verify the installation. The check above verifies imports and GPU conditions only; it does not establish that model loading or training succeeds. Download scripts require network access and additional disk space. See the upstream pages for model and dataset licenses. The [ScienceQA dataset card](https://huggingface.co/datasets/derek-thomas/ScienceQA) is inconsistent: its metadata specifies CC BY-SA 4.0, whereas its licensing section specifies CC BY-NC-SA 4.0 and its text limits use to non-commercial research. Confirm the applicable terms with the upstream provider before use.

## Workflow

Run the commands below from the `vision-decision/` directory.

### 1. Download the backbone and data

```bash
# Choose a new working directory outside the repository; downloads are large
VISION_WORK="$(mktemp -d "${HOME}/vision-decision-XXXXXXXX")" || exit 1
export VISION_WORK
python scripts/download_backbone.py --size 2b --dest "$VISION_WORK/models"
python scripts/download_data.py --dest "$VISION_WORK/data"
```

Both downloaders use the official Hugging Face endpoint by default. Add `--mirror` explicitly if needed; they also honor an existing `HF_ENDPOINT`. They refuse to overwrite an existing model or data destination. If a download is interrupted, inspect and keep existing files, then retry with a new path. Dataset and model revisions are not pinned, so record the versions actually used for later review.

### 2. Split the data

The original ScienceQA file is under `data/` in the download directory, with a hash in its filename. Pass the download directory and the script recursively searches for `test-*.parquet`. It proceeds only if exactly one file matches; zero or multiple matches cause an error. You may also pass a specific, verified Parquet file directly:

```bash
python scripts/prepare_data.py "$VISION_WORK/data" "$VISION_WORK/prepared-clean-v1"
```

The outputs are `$VISION_WORK/prepared-clean-v1/{train,dev,calibration,test}.jsonl` and `$VISION_WORK/prepared-clean-v1/split_manifest.json`. The script stops if a target file already exists. To save another copy, pass a new output directory after the input file.

The split key is image SHA-256, not row ID. Keeping the same image in one split helps reduce image leakage, but does not eliminate duplicate or semantically repeated questions and text. The new version builds model input only from the question, options, and prompt; it does not use `lecture` or `solution`. The defaults select 100 test, 400 train, 100 dev, and 100 calibration images, in that order and in source-row order, without shuffling. All four splits come from the upstream test file; they are not the official ScienceQA splits and results cannot be directly compared to official-split results. The source test file has 4,241 rows, so the former quota of 4,800 distinct images was impossible. Change the quotas using `--test-cases`, `--train-cases`, `--dev-cases`, and `--calibration-cases`; insufficient unique images cause an error before partial splits are written. Use the generated `prepared-clean-v1/split_manifest.json` for actual row counts and duplicate/invalid scan hits; a source row can be scanned and counted in multiple split passes. Keep the historical `prepared/` data as an old record; training and evaluation reject data without the new-version marker.

Each row contains:

| Field | Meaning |
|---|---|
| `image_png_b64` | Base64-encoded image |
| `state` | Candidate answers and prompt |
| `context_hint`, `input_schema` | Input prompt and data-format marker |
| `question` | Decision question |
| `options` | Candidate list |
| `gold` | Probability distribution: 1.0 for the correct option and 0 for the others |

A lightweight regression check uses synthetic inputs and a tiny test-double model to verify that one training step changes a parameter. It does not download the backbone:

```bash
python tests/test_training_update.py
```

The test requires a CUDA GPU with bfloat16 support and reports a skip otherwise. It does not validate Qwen, LoRA, or training on real image-text data.

To first check training with a real backbone and data, download the smaller model and use the first example from each split:

```bash
python scripts/download_backbone.py --size 0.8b --dest "$VISION_WORK/models" --revision 2fc06364715b967f1860aea9cf38778875588b17
python scripts/train.py \
  --model "$VISION_WORK/models/Qwen3.5-0.8B" \
  --data "$VISION_WORK/prepared-clean-v1" \
  --out "$VISION_WORK/smoke" --steps 1 --bs 1 --max-cases-per-split 1
```

This saves a one-step adapter and its metrics are not statistically meaningful. Use a new output path; adjust `--mem-min-start`, `--mem-min-run`, and `--mem-cap` for the device.

### 3. Train

```bash
python scripts/train.py \
  --model "$VISION_WORK/models/Qwen3.5-2B" \
  --data "$VISION_WORK/prepared-clean-v1" \
  --out "$VISION_WORK/run" \
  --steps 1200 \
  --bs 2
```

Training and standalone evaluation require the output directory to be missing or empty. For another run, choose a new path for `--out` so existing weights and results are not overwritten. The script saves the last step and does not select a checkpoint using the development set; fix the training parameters before inspecting test results.

Before training, the script reads `MemAvailable` from `/proc/meminfo` and refuses to start if it is below `--mem-min-start` (25 GB by default). After each backward pass it checks system available memory and this process's peak PyTorch CUDA tensor allocation. If available memory falls below `--mem-min-run` (45 GB by default) or tensor allocation exceeds `--mem-cap` (70 GB by default), training stops, saves the current state, writes `aborted.json`, and exits without evaluation. Tensor allocation is not total GPU usage; checking only after backward cannot prevent every out-of-memory failure.

This guard is mandatory. Qwen3.5 combines Gated DeltaNet with gated attention, so its activation-memory profile differs from a standard transformer. The default reentrant implementation of `gradient_checkpointing_enable()` may silently fail on this kind of nonlinear structure. The script explicitly passes `use_reentrant=False`. Scaling up the model or batch can still exhaust system resources, so the guard remains in place.

### 4. Evaluate

The evaluation built into the training script sends the same image through the processor repeatedly, once per candidate. The processor's `smart_resize` is a single-threaded, CPU-intensive operation; 1,000 test examples can take more than ten minutes. The standalone evaluator first reduces images using limits on both the longest edge and total pixel count, leaving only normalization for the processor. Both built-in and standalone evaluation process one question at a time to limit batch size; evaluation can still exhaust memory depending on inputs and hardware:

```bash
python scripts/evaluate.py \
  --model "$VISION_WORK/models/Qwen3.5-2B" \
  --ckpt "$VISION_WORK/run/final" \
  --data "$VISION_WORK/prepared-clean-v1" \
  --out "$VISION_WORK/eval"
```

The temperature grid contains 41 points from 0.5 to 4.5 and is fitted only on the calibration set. The grid built into `train.py` has an upper bound of 2.0; the measured optimum reached that bound, so a wider range is needed.

### 5. Start the service

```bash
python scripts/serve.py --ckpt "$VISION_WORK/run/final" --model "$VISION_WORK/models/Qwen3.5-2B" --port 8010
```

```bash
curl -X POST http://127.0.0.1:8010/decide -H 'Content-Type: application/json' -d '{
  "image_png_b64": "<base64>",
  "state": "Candidate answers:\nA. ...\nB. ...\n\nHint:...",
  "question": "What is happening in the image? Choose the correct candidate answer.",
  "options": ["A. ...", "B. ..."]
}'
```

The response contains `probs`, `prediction`, and `confidence`.

## Differences from agent-jev-text

| Dimension | agent-jev-text | vision-decision |
|---|---|---|
| Backbone | Qwen3-0.6B | Qwen3.5-2B |
| Data | typed-decisions | ScienceQA |
| Fine-tuning | Full-parameter | LoRA r=16 |
| Input | Context + candidate text | Image + context + candidate text |
| Image placeholder | None | `<|vision_start|><|image_pad|><|vision_end|>` |
| Split key | case ID | image SHA-256 |
| Memory management | None | Startup check + runtime hard guard |

## Known limitations

An old data-preparation script included ScienceQA's `solution` (reference-answer reasoning) in the model input, affecting historical training and evaluation. A small training run and separate-split test have completed on corrected data, but the planned training and an independent test of visual ability remain outstanding. An archived public training script lacked `optimizer.step()`. The exact script snapshot used for the historical run has not been found, so whether its weights changed is unknown. Training resume, standalone evaluation, and the service entry point check the weights' data-format marker and reject old weights without it. Image-hash deduplication and field filtering also cannot rule out leakage through repeated questions, prompts, or near-duplicate images. `gold` represents a multiple-choice answer key; it is not a real-world action success probability.

As of February 2026, the Qwen3.5 series uses a unified multimodal backbone, and the earlier Qwen-VL product line has been discontinued. Do not apply Qwen2-VL or Qwen2.5-VL placeholders or processor conventions here.
