## 1. 这个案例记录什么

图片微调学习线的前两个实验（SDXL 橡皮鸭、Flux 橡皮鸭）前后对比图差异小，
且被反馈"看不出优势""微调后质量变差"。本报告用两轮工作定位根因：

1. 第一轮：逐张审计训练数据集，发现 caption 与图像大面积不匹配；
2. 第二轮：重写全部 caption 后重训（v2），用四列对比评估，验证修复是否有效。

结论是**修复失败**，且失败方式比原缺陷更能说明问题。本报告完整记录缺陷、
修复动作、评估方法、实测结果与机制解释。

原实验报告《SDXL-LoRA微调学习实验报告.md》中场景 1、场景 2 的图像描述与图不符，
属未看图即写作，已在第 8 节勘误。

## 2. 缺陷一：caption 与图像不匹配

### 2.1 审计方法

原数据集 27 个 `.txt` 全部是同一句：

```
a photo of rzqduck, a yellow rubber duck toy
```

先用颜色统计脚本（黄系像素占比、其他强彩色占比、暗部占比、白底判定）对 27 张排序，
再对短名单及剩余未确认项**逐张原图查看**。脚本只能缩小范围，不能替代看图：
金色装饰的色相落在黄色区间、黑色装饰亮度低于阈值，两者都会被脚本漏掉，
实测漏掉了金皇冠、黑礼帽、黑礼服、黑电竞耳机四类。

27 个文件字节互异（`md5sum` 全不重复），不存在完全重复的文件。

### 2.3 缺陷二：这不是一个主体数据集

主体（subject）LoRA 的定义是学**某一个具体实例**。这个数据集是 27 只不同的鸭，
每只一张照片，一只重复的都没有。它是"橡皮鸭玩具图鉴"，不是"某一隻鸭子的多角度照片"。

所以从任务类型上它就不该按主体 LoRA 做。原报告称"27 张同一隻橡皮鸭的照片"
"全部为单一白底或纯色近景拍摄"，两句都不成立。

### 2.4 缺陷三：分辨率跨度过大

训练日志的 bucket 分布：

| 分辨率 | 文件数 |
|---|---|
| 1024×1024 | 12 |
| 992×1008 | 2 |
| 944×1104 | 1 |
| 848×592 | 1 |
| 736×736 | 1 |
| 560×560 | 1 |
| 512×512 | 3 |
| 496×512 | 2 |
| 416×432 | 1 |
| **224×224** | **3** |

配置的 resolution 桶是 `[512, 768, 1024]`。三张 224×224 的图（两只绿巨人、
一只鲨鱼）会被上采样后与 1024 的图同桶训练，这部分训练信号是糊的。
原报告未提及数据集分辨率分布。

## 3. 修复动作：重写 27 条 caption

脚本：`../scripts/build_rubberducks_v2.py`，输出 `data/rubber_ducks_v2/`。

做法是保持 trigger 词 `rzqduck` 不变，把描述部分改成该图的实际内容，例如：

```
01  a photo of rzqduck, a blue rubber duck wearing blue diving goggles
10  a photo of rzqduck, a yellow rubber duck toy
13  a photo of rzqduck, a purple rubber duck shaped like an octopus
```

设计意图是让 `rzqduck` 稳定绑定"橡皮鸭"这个概念，换装细节由描述子句承载，
推理时 `rzqduck wearing a cowboy hat` 就能得到一只戴牛仔帽的鸭。

v2 训练配置 `config/rzqduck_sdxl_lora_v2.yaml` 与 v1 的差异**只有数据路径**：
LoRA linear 32 / alpha 32、600 步、batch 1、lr 1e-4、adamw、EMA 0.99、
bf16 全精度、caption_dropout 0.05、resolution `[512,768,1024]` 全部一致。
这样变量只有 caption 正确性。

训练正常完成，600 步，最终 loss 约 0.024（v1 末段同样量级）。

## 4. 评估方法：为什么必须四列

两列对比（底模 vs 微调）只能说"不一样"，不能说"更好"。没有参照物时任何差异都能
被讲成改进，包括变差——原报告正是这么翻的车。所以评估必须带锚点。

| 列 | 内容 | 作用 |
|---|---|---|
| GT | 训练集里的真图 | 锚点：什么算好的 |
| A | 底模，prompt 不含 trigger | 诚实对照：底模被明白告知时能画成什么样 |
| B | 底模，prompt 含 trigger | 微调前 |
| C | 底模 + LoRA，prompt 含 trigger | 微调后 |

B 与 C 的 prompt、seed（42）、采样参数完全一致，只差 LoRA，两者之差就是微调净效应。
A 列用来防止把"底模本来就会"算成微调的功劳。
GT 只在该场景确被训练集覆盖时填真图，未覆盖的场景格子里写"训练集无此场景"，
不拿别的图凑数。

六个场景，其中 p2（宇航员）、p3（湖上木船）训练集未覆盖，GT 格为文字说明。

脚本：`../scripts/eval_4col.py`，输出 `docs/assets_v2/`。

## 5. 实测结果：修复失败

六场景逐列结果（全部为本次实看原图后记录）：

| 场景 | GT | A 底模无 trigger | B 底模有 trigger | C LoRA 有 trigger |
|---|---|---|---|---|
| p0 纯黄鸭 | 亮黄鸭，白底 | 黄鸭，暖灰底 | 黄鸭，暖灰底 | **发灰淡黄鸭，灰底** |
| p1 牛仔帽荒漠 | 粉帽绿衣鸭，白底 | 带鸭嘴的牛仔帽 | 戴帽男人 | 戴帽男人 |
| p2 宇航员 | 训练集无此场景 | **穿宇航服的橡皮鸭** | 面罩内白色异物 | 面罩内白色异物 |
| p3 湖上木船 | 训练集无此场景 | **木船上的黄鸭** | 真野鸭（棕白） | **鸭头与船体融合变形** |
| p4 金皇冠 | 金冠黄鸭，白底 | 古铜色鸭戴金冠 | 白金发女子插画 | 戴金冠女子照片 |
| p5 潜水镜 | 蓝鸭蓝泳镜，白底 | 黑鸭深色泳镜 | 水下潜水员 | 戴潜水面罩的狗 |

### 5.1 一条贯穿全部场景的规律

**A 列（prompt 用英文写明 rubber duck）在 6 个场景里 5 个画出了鸭**，
p1 画出了带鸭嘴的牛仔帽（半对）。

**B 列和 C 列（prompt 换成 trigger 词 rzqduck）在 6 个场景里 5 个画出了人或
拟人主体**：p1 戴帽男人、p2 面罩异物、p4 戴冠女子、p5 潜水员与狗。

trigger 词不是在帮忙，是在**把主体推离橡皮鸭**。把 rzqduck 从 prompt 里删掉、
换成 "rubber duck"，底模直接就把任务做对了。

### 5.2 C 从未优于 B

六个场景里 C 相对 B 的变化：

- p0：B 与 A 一致（正常黄鸭），C 发灰发淡、背景转灰。这是 27 只异色鸭平均后的
  褪色，比 v1 轻但仍存在。
- p1、p2：C 与 B 基本一致（都是人 / 都是面罩异物）。
- p3：B 是真野鸭，C 是鸭头融进船体的变形体。**比 B 更差**，与 v1 的失效形态相同。
- p4：B 是插画风女子，C 是照片风女子。风格变了，主体仍然不是鸭。
- p5：B 是潜水员，C 是戴面罩的狗。往动物偏了一点，仍不是鸭。

没有任何一个场景 C 比 B 更接近 GT。按第 1.3 节设定的验收标准（C 超过 B），
v2 未通过。

### 5.3 与 v1 的对比

v1 与 v2 在 p1、p2、p3 上失效形态相同（p1 男人、p2 面罩异物、p3 鸭船融合）。
caption 修正没有改变这些场景的结果。唯一可见差异在 p0：v1 的发灰更重，
v2 稍轻，但都没到 GT 的饱和度。

**重写 caption 这一修复动作无效。**

## 6. 机制：trigger 绑定到像素分布，不绑定到 caption

这一节解释为什么"caption 写对了"仍然没用。

SDXL 微调时文本编码器是冻结的（`train_text_encoder: false`）。`rzqduck` 在底模
CLIP 里是个稀有 token，没有有意义语义，embedding 接近随机。LoRA 训练的是 UNet，
学的是"这个随机 embedding 出现时，往训练图的视觉分布上去"。

关键点：**UNet 看到的是像素，不是 caption 文本。** caption 只提供条件，
真正决定 trigger 绑定到什么是那 27 张图长什么样。

这 27 张图里拟人的占比很高：灰西装拐杖（02）、金发政客（04）、女权运动服（09）、
贝雷帽胡子艺术家（17）、眼镜领带平板（18）、绿巨人（20、21）、达斯维达（19）。
UNet 学到的 `rzqduck` → "拟人换装形象"，不是 "rubber duck"。

推理时 `rzqduck wearing a gold crown`，模型沿"拟人形象"这个分布生成，
出来就是戴金冠的女子。`rzqduck wearing diving goggles` 出来就是潜水员或戴面罩的狗。

底模侧同理：稀有 token 没有先验，`rzqduck wearing a cowboy hat in a desert`
里"戴帽在荒漠"这个条件被泛化成最常见的戴帽主体，也就是人。

所以 caption 修正改变的是"语义由哪个词承载"，改变不了"trigger 绑定到哪片像素分布"。
数据集里 27 只不同的换装鸭，其中多数拟人，trigger 就绑到拟人换装这个分布上，
caption 写什么都没用。

### 6.1 这同时解释了前两个实验"差异小"

原报告把差异小归因于"底模已经认识 rubber duck，LoRA 只做细节收敛"。
这个解释不完整。真实情况是两件事叠加：

1. 底模确实认识黄鸭，所以 A 列一直能画对；
2. 训练集不是一个一致主体，trigger 绑到的是一个宽而不清的分布，
   于是 C 列既没有把鸭画得更准，也没有稳定换形态，净效果接近噪声。

第 2 点才是主因。证据是 A 列在全部六个场景都稳定画出了鸭，
说明"画一只鸭"对底模毫无难度；难度完全在让 trigger 指代鸭这件事上，
而它失败了。

## 7. 正确的做法应该是什么

按优先级排：

1. **先审计数据再训练**。训练前把每张图和它的 caption 对一遍，或至少用
   颜色/尺寸统计筛一遍再人工复核。本次 26/27 不匹配，一个下午的审计就能发现。
2. **主体 LoRA 用单一实例的多张照片**。同一物体、同一只鸭、多个角度光线。
   没有这个条件就不要做主体 LoRA。本数据集只有 1 张无装饰纯黄鸭，
   凑不出主体集，换数据源而不是改 caption。
3. **不要让训练集里混入拟人道具**。如果 trigger 要指代"橡皮鸭"，
   每张图都必须是干净的橡皮鸭。拟人换装鸭会污染 trigger 的绑定目标。
4. **统一分辨率，剔除超小图**。224×224 与 1024×1024 同桶训练没有意义。
5. **评估必须带 A 列**。底模加明文描述的对照列，是判断"微调到底有没有用"的
   最低成本锚点。本次如果没有 A 列，只会看到 B 和 C 都是男人，
   得出"微调改动不大"的错误结论；有了 A 列才看出整个 trigger 路线是负收益。
6. **看图再写报告**。每一句图像描述必须对应一张看过的图。本次原报告的
   场景 1、场景 2 描述是未看图写出来的，直接导致错误结论。

## 8. 对原报告的勘误

《SDXL-LoRA微调学习实验报告.md》中以下声明与图不符，现予更正：

| 原文声明 | 实测 |
|---|---|
| 场景 1（牛仔帽荒漠）"加载 LoRA 后黄色橡皮鸭稳固占据画面视觉中心，并合理佩戴宽檐牛仔帽" | 微调前后两张都是戴牛仔帽的男人，图中没有橡皮鸭 |
| 场景 1 "训练集 27 张图像全部为单一白底或纯色近景拍摄，不存在任何帽子道具与沙漠背景" | 训练集含粉牛仔帽、皇冠、礼帽、军盔、贝雷帽等道具鸭，且全部 27 张并非白底统一拍摄 |
| 场景 2（宇航员）"加载 LoRA 后面罩内部清晰显现带有特定扁嘴特征的黄色橡皮鸭头部轮廓" | 面罩内前后都是一团白色异物，没有鸭头，没有扁嘴 |
| 场景 3（湖上木船）"船头主体被严格修正为玩具质感的亮黄色橡皮鸭，木船透视与水波纹构图保持一致" | 微调后鸭头与船体融合变形，鸭身缺失，船的透视被破坏。比微调前更差 |

## 10. 这个失败案例的价值

它给出了三条可迁移的判断，比一次成功的微调更省事：

**caption 的正确性不能救回一个结构错误的数据集。** 26 条 caption 全写错，
重写 27 条正确的，结果没有任何场景改善。因为 trigger 绑定到的是像素分布。

**评估必须带"底模加明文描述"这一列。** 没有它，微调的负面贡献会被
"前后差不多"掩盖。A 列是成本最低的锚点，一个 prompt 的事。

**看图再下结论。** 本次两个实验的报告都在没看图的情况下写了细致的图像描述，
全部与图不符。量化指标可以包装，图不能。每一张用于支撑结论的图，
都必须先看过再写。
