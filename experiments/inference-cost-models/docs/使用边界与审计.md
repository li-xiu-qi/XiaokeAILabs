# 使用边界与审计

本实验的历史脚本和报告包含有价值的推导线索，但尚不能用作可靠的跨硬件或跨工作负载性能预测。2026-11-07 的代码审阅发现以下问题；记录保留用于追溯，历史结论以本页为准。

- 引擎比较脚本以整次 HTTP 请求计时，时间中混有排队、输入处理、生成和网络，历史数字不能解释为纯 prefill 或 decode 吞吐，也不能据此断定引擎差异的原因。
- 单点测量反推的带宽系数代回同一点不构成独立验证；该反推量依赖权重读取字节数等假设，也不是硬件计数器测得的真实流量。LLM-Viewer 对照中的误差拆分及瓶颈归因尚未证实。
- 不同记录中权重文件大小、GB/GiB、设备容量和 Q4 文件口径不一致，需核对具体模型文件和字节数。权重精度不能决定 KV 精度。
- 原注意力脚本漏乘查询头数、把混合架构所有层当成全注意力，并将各层分数矩阵之和误称峰值显存。现已修正为明确假设的示例，实际计算和峰值内存仍应实测。
- 其他脚本仍可能存在无效 batch 参数、跨精度的峰值算力套用、未验证的吞吐效率，以及推测解码跨引擎比较；暂不应将其数字用于外推。不同版本中的硬件参数和内存估算同样需要逐项核验。

下一步应保留可复现的模型文件信息和基准原始记录，修正其余脚本并分别测量阶段延迟，在未参与标定的负载上验证预测；瓶颈归因需 profiler 或硬件计数器支持。

## 脚本可用范围

- `attention_model.py`：非因果稠密全注意力的操作量和单层分数矩阵理论算例，非实际延迟或峰值内存。
- `hybrid_architecture_model.py`：命令行接受指定层数、头数、KV 精度、长度和 batch，估算标准 KV 字节。FP8 和 FP4 仅按理想元素位宽计算，未包含量化元数据；不含混合层状态和运行时开销。所有 `_gb` 结果为十进制 GB，命令行同时显示 GiB。旧的模型命名函数仍属未核验的历史示例，不应作为模型配置来源。
- `compare_engines.py`：按用户指定的 prompt 和模型记录单次请求总耗时及服务器返回的真实 token 数；不测阶段吞吐。需要安装 `requests` 和可用服务；暖机、重复次数和请求分布需自行设计。
- `roofline_model.py`：理论数据移动算式仍可作为阅读材料，但运行入口和无法支持的瓶颈、MoE 及 prefill 判断已禁用；其中 decode 简化函数不是经验证速度预测。
- `embedding_throughput_model.py`：缺少可核验原始样本，吞吐预测已禁用；不得由拟合推断 Python 或 GPU 瓶颈。`kv_cache_model.py` 的旧演示入口已禁用，因其总内存和最大上下文示例缺乏充分证据。

运行 `python -m unittest discover -s tests -v` 检查 KV 的字节换算、batch 缩放、权重与缓存精度独立性和未验证预测的拒绝行为。其余脚本仍须独立审计。

## 本轮修复与未解决问题

旧版 `test_vllm.py`、`test_sglang.py` 和三个对应 shell 测试把整次请求时间错误命名为阶段吞吐，现已阻止执行；请求级计时使用 `compare_engines.py`，它不能替代阶段指标。`llm_viewer_comparison.py` 原有结论依赖不匹配的时钟口径，已阻止执行。

`throughput_model.py`、`weight_memory_model.py` 和 `memory_hierarchy_model.py` 的历史演示入口已禁用，内含未经独立验证的效率、瓶颈判断及外推；保留源代码供检查，不应用其函数进行部署预测。`llm_spec.py` 的 128 GB 是设备标称十进制容量，不是当前可用内存；其余旧示例参数和基准口径未经独立核实。

`speculative_model.py` 现在仅计算固定条件接受率、忽略 EOS 且每轮额外输出一个修正或奖励 token 的期望值。速度比例依赖调用者假设的草稿和验证成本，不从跨引擎数值推算，也不代表设备实测。
