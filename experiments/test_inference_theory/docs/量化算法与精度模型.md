# 量化算法与精度模型

量化算法的名字很多（GPTQ、AWQ、NVFP4、Q4_K_M、AQLM），但都在解决同一个矛盾：多少个权重共享一把精度尺子（scale）。抓住这条主线，分类和取舍就有了一致的内在逻辑。

## 主线：多少个权重共用一把 scale

低比特量化无法给每个权重单独配一把满精度的尺子，只能一群权重共用一把。这群有多大、尺子多细，直接决定精度。这正是 NVFP4 和 MXFP4 的全部差别（来源：NVIDIA 官方与社区对比，2025）：两者都是 4-bit 浮点 E2M1，MXFP4 是 32 个权重共用一把只能按 2 的幂调节的尺子（E8M0 scale），NVFP4 是 16 个共用一把 FP8 精度的细尺子（E4M3 scale）外加一层张量级 FP32 缩放。结果 NVFP4 平均多花 0.25 bit（4.5 vs 4.25），但精度明显更好。

GPTQ 论文实测的 group_size 有 1024 和 128（3 bit）、128/64/32（2 bit）、8（ternary），但**主实验全部是 row-wise（不分组）**，grouping 只是「附加手段」，论文没有「默认 group_size」这一说法。社区代码里的 `-1` 表示不分组是代码约定，不是论文表述。GGUF 的 256 元素 super-block、AWQ 的显著通道保护，本质都在回答这个「共享粒度」问题。所以判断一个量化方案，先看它让多少个权重共用一把尺子、尺子多细，比记算法名字有用。

## 两个范式：整数量化 vs 浮点微缩放

**整数量化（INT）**：把权重映射到整数格点，一群权重配一个整数 scale。代表是 GPTQ（Hessian 逐层二阶补偿，arXiv 2210.17323）、AWQ（激活感知，保护显著权重通道，arXiv 2306.00978）、GGUF k-quants（Q4_K_M/Q5_K_M/Q6_K）、AQLM（加法量化码本，能压到 2-3 bit）、bnb（LLM.int8()，离群值单独保 FP16，arXiv 2208.07339）。这一类是过去两年的主力，生态最成熟。

**浮点微缩放（FP microscaling）**：Blackwell 时代的新路线，保留浮点的动态范围（不像整数把分布硬切格点），靠两级 scale 解决离群值。代表是 NVFP4（NVIDIA 原生）和 MXFP4（OCP 开放标准）。这类是 GB10 的独有优势，4090 没有原生 FP4。

## 具体算法清单（按生态分）

llama.cpp/GGUF 生态：legacy 的 Q4_0/Q4_1/Q5_0/Q5_1/Q8_0 已过时，现在主力是 K-quants（Q2_K 到 Q8_K）。K-quants 用 256 元素 super-block 两级 scale，不需要校准数据（纯舍入），所以量化快、通用。unsloth 的 UD-Q4_K_XL 是在 Q4_K_M 基础上调的变体，实测 27.3B 模型约 0.60 B/param。

GPU 推理生态：GPTQ 要校准数据加 Hessian 二阶信息，精度好，GPU 上有专用 fused kernel；AWQ 按激活幅值找出显著权重通道重点保护，要少量校准数据（16 条序列即可达到优于 GPTQ 192 条序列的效果）；EXL2 是 GPTQ 的变体支持混合 bit-width。这几个在 vLLM/SGLang 上跑。

**关于 AWQ 与 GPTQ 的精度对比存在论文冲突**：AWQ 原论文（2306.00978）称在 WikiText PPL 上稳定优于 GPTQ；但 BF16-or-Death（2411.02355）用更严格的真实世界基准复测，称 GPTQ 简单变体在真实任务上反超 AWQ（8B 差 2.9 分），归因于 AWQ 对比时超参选择次优。**这一争议未解决**，本实验不采信任一方，只记录两者精度差距在实际场景中可能小于论文宣称。

极限压缩：AQLM 用码本加法组合，能压到 2-3 bit，适合极端显存受限；SpQR 把离群值单独存高精度，其余走低位宽。

## 对速度的影响：weight-only 与激活量化的机制差异

这是唯一能用公式算死的部分，依据 Roofline 模型：decode 是带宽瓶颈，tok/s = 带宽 / 权重字节。所以 weight-only 量化（只压权重、激活保高精度）对 decode 的提速 ≈ 字节比的反比。bf16（2.0 B/param）到 Q4（约 0.58 B/param）提速约 3.3 倍，和 GB10 上 Qwen3.8-27B 实测的 4.3→12.1 t/s（2.8 倍）基本吻合，差的部分是带宽利用率和 kernel 效率。

论文指出这一机制在 GPTQ（2210.17323）与 SmoothQuant（2211.10438）中均被独立确认：GPTQ 的加速全部来自减少显存搬运而非减少计算，其 3-bit kernel 在 A100-80GB 上实测 3.24 倍；SmoothQuant 在附录中明确区分了 weight-only 路线（即时反量化回 FP16 做 matmul，只省带宽）与 W8A8 路线（用上 INT8 GEMM，收益在算力）。

但要分清两种量化对速度的作用路径不同。Weight-only 量化提速靠「读进来的字节少了」，decode 阶段直接受益；它不改变算力（权重反量化回 BF16 再做矩阵乘），所以对 prefill（算力瓶颈）几乎没提速，这一点常被误解。真正影响算力的是 W8A8、W4A4 这类激活也量化的方案，把矩阵乘降到低比特 tensor core，但需要校准、精度损失更大。

还有个坑：量化不一定自动提速。如果推理框架没有专用的反量化 kernel（某些框架直接加载量化权重再反量化），反量化开销会吃掉带宽收益。GGUF 在 llama.cpp、GPTQ/AWQ 在 vLLM/SGLang 上都有专用 kernel，所以能提速。

## 对智力的影响：经验性、任务相关，没有普适公式

这块不像速度那样有物理公式。Perplexity（困惑度）是常用代理指标，但不直接等于下游任务表现。给几条有数据支撑的规律。

按比特数的经验分层（来源：Llama-2 系列实测，datawhale base-llm 教材；其中 4-bit 数字经 AWQ 论文 2306.00978 Table 4 核对一致）：8-bit（Q8）perplexity 几乎无损（差 0.1 以内）；6-bit（Q6_K）接近无损；5-bit（Q5_K_M）微小损失；4-bit 是甜点，大模型上损失很小（Llama-2-70B 的 AWQ INT4 困惑度 3.41，FP16 基线 3.32）；3-bit 开始有明显损失；2-bit 损失显著，除非模型冗余足够多。

**激活量化比权重量化难**，这是论文指出但文档易漏的一条：BF16-or-Death（2411.02355）发现 W4A16-INT 的恢复率反超 W8A8-INT，原文结论是「for INT, quantizing activations is harder than quantizing weights」。GPTQ（2210.17323）也明确把「不量化激活」列为自身局限。

大模型对量化明显更鲁棒，这是最该记住的规律。GPTQ（2210.17323）的 OPT 系列数据最能说明：4-bit 下 OPT-125M 困惑度从 27.65 涨到 31.12（+3.47），13B 从 10.13 涨到 10.31（+0.18），175B 从 8.34 涨到 8.37（+0.03），损失随规模单调收敛。

但要注意这条在 AWQ（2306.00978）数据上不那么明显：Llama-2-13B 的 INT4 绝对损失 0.09、70B 也是 0.09，绝对值几乎相同。两者的差别可能来自模型系列与量化方法，**「大模型更鲁棒」目前只有 GPTQ 的 OPT 系列提供了单调证据**，不宜当作跨方法的普适规律。

任务相关性强：分类、embedding、检索这类判别式任务对量化最鲁棒；开放式生成、复杂推理、代码数学更敏感。同一 Q4，做情感分类可能无感，做数学证明可能掉好几个点。

（此条为**经验性归纳**，五篇论文均未直接支撑。可参照的间接证据是 BF16-or-Death 2411.02355 的恢复率数据：其 Leaderboard V1 上 8-bit 平均恢复 99.75%、W4A16-INT 99.36%，但 TruthfulQA 单任务最低跌到 96.88%，说明任务间差异确实存在，只是「判别式 vs 生成式」这个二分未经该文验证。）

NVFP4 有个反直觉的实测数据值得注意（来源：NVIDIA 官方，2025）：Gemma 4 31B 量化到 NVFP4 后，GPQA Diamond 保留 99.7% 精度（75.46% vs 原版 75.71%），AIME 2024 甚至比 FP8 还高 2%。社区推测微块缩放在特定数据分布下起了正则化作用。这说明 FP4 浮点加微缩放，在大模型上能做到接近无损，颠覆了「4-bit 必掉点」的旧认知。

注意此条来源为 NVIDIA 官方而非论文：已下载的五篇量化论文中，BF16-or-Death（2411.02355，成文于 2024 年 11 月）全文未涉及 NVFP4/MXFP4/FP4，其最低位宽只到 INT4，且对更激进的表示（AQLM、QuIP# 等）给出负面判断，认为它们「在 batch size 大于 1 时效率低下」。FP4 微缩放的系统性评估仍缺论文级公开证据。

## 落回 GB10 场景

NVFP4 是 GB10 区别于 4090 等卡的独有武器，原生 FP4 tensor core。llama.cpp Q4_K_XL（12.1 t/s）走的是整数量化加软件反量化，没用上原生 FP4。社区在 GB10 上把 Qwen3.8-27B 跑到 23 t/s 单流（来源：2026-08 阿里云实测），用的是 SGLang 加 RadixArk NVFP4 加 NEXTN 投机采样。所以要榨干 GB10 的速度，方向是 NVFP4 加 SGLang，不是在 llama.cpp 的整数量化上继续调。

以 Qwen3.8-27B 加 GB10 的 273 GB/s 带宽，量化方案的选择逻辑是：bf16 全量（4.3 t/s）验证精度基线，NVFP4（约 15GB）作为主力精度速度平衡点，Q4_K_XL（16.4GB，12.1 t/s）作为不依赖 FP4 硬件的兜底。三者横向对比一轮 NVFP4 相对 BF16 和 Q4 的精度速度差，是 GB10 上最有价值的实测。
