# 内存层级与卸载模型

> 实证日期 2026-09-08 · Python 3.13.0 · 脚本 `scripts/memory_hierarchy_model.py` · 对齐 GB10 -ngl 0/32/99 实测

decode 是带宽瓶颈，tok/s = 有效带宽 / 权重字节。有效带宽取决于权重在内存层级的哪一层。这个模型回答：权重放不同内存层级，decode 速度掉多少，以及为什么 GB10 的统一内存能「假装」有大显存。

## 内存层级的带宽阶梯

权重可能分布在三层，带宽差两个量级：

| 层级 | 带宽 | 说明 |
|---|---|---|
| GPU 显存 | 约 1000 GB/s | 离散 GPU 的 HBM |
| CPU 内存 | 约 50 GB/s | DDR |
| NVMe 磁盘 | 1.3 GB/s（GB10 实测） | 最后一层 |

带宽越低，decode 越慢，因为每个 token 都要把权重从所在层级搬到计算单元。

## 核心分野：统一内存 vs 分层内存

这是这个模型的关键，也是 GB10 区别于离散 GPU 的地方。

**GB10 统一内存**：CPU 和 GPU 共享同一条 273 GB/s 总线，没有 PCIe。无论权重标称在 CPU 侧还是 GPU 侧，带宽都是 273 GB/s。所以部分卸载（-ngl 部分层）不会速度断崖，只降一点计算效率（CPU 核做矩阵乘比 GPU 慢）。实测（2026-09-08，Qwen3.8-27B bf16）：

| -ngl | GPU 侧比例 | 实测 decode |
|---|---|---|
| 0（全 CPU） | 0% | 1.5 t/s |
| 32（一半） | 50% | 2.1 t/s |
| 99（全 GPU） | 100% | 4.7 t/s |

全 CPU 到全 GPU 只差 3 倍，因为带宽没丢，丢的是计算效率。模型对 -ngl 0 和 99 的预测误差 0% 和 6%，中间点 -ngl 32 误差大是因为计算效率不是线性，但趋势正确。

**离散 GPU（如 4090）**：显存和 CPU 内存是两条总线，CPU 内存的权重要经 PCIe（约 30 GB/s）搬运。一旦卸载到 CPU 内存，PCIe 成瓶颈，速度断崖。模型外推：54.6GB 的 bf16 权重在 4090 上卸载后，有效带宽掉到 PCIe 的 30 GB/s 量级，decode 约 0.5 t/s，比 GB10 全 CPU 的 1.5 t/s 还低。

## 这对部署意味着什么

GB10 的统一内存让「权重放不下就跑 CPU 侧」成为可行策略，速度只降 3 倍而非 10 倍。所以 GB10 能跑显存装不下的大模型（靠统一内存兜底），而离散 GPU 一旦超过显存就必须靠磁盘 offload，速度崩溃。这是 GB10 跑超大模型（如 320B MoE 量化版）的物理基础。

磁盘作为最后一层（mmap 加载），1.3 GB/s 带宽下 bf16 54.6GB 权重的 decode 上限只有 0.02 t/s，实际不可用，只适合超大模型的极限场景，且靠页缓存把热权重留在内存、冷权重留磁盘。

## 按层累加：为什么中间档必须逐层算

2026-09-08 修正。旧版用「有效带宽 × 混合计算效率 × 单一利用率系数」，两端点能拟合，中间档误差爆炸：

| -ngl | 实测 | 旧版预测 | 旧误差 | 新版预测 | 新误差 |
|---|---|---|---|---|---|
| 0 | 1.5 t/s | 2.1 | **43%** | 1.5 | 0% |
| 32 | 2.1 t/s | 3.4 | **63%** | 2.3 | 8% |
| 99 | 4.7 t/s | 4.7 | 0% | 4.7 | -1% |

根因是两个端点的**服务效率差 3 倍**，单一系数覆盖不了。用两端实测反推每层有效服务带宽：

- GPU 层：54.6GB ÷ 64 层 ÷ 3.33ms = **254 GB/s** = 273 峰值的 93%
- CPU 层：54.6GB ÷ 64 层 ÷ 10.42ms = **81 GB/s** = 273 峰值的 30%

两者读同一条物理总线，带宽峰值相同，差距纯粹来自访问效率。这与 arXiv 2512.01644 的实测吻合：decode kernel 的 GPU Execution 只占 24%，70%+ 周期停在访存 stall 上；CPU 侧 GEMV 的访存模式更差。

新版 `decode_tps_layerwise()` 按层累加服务时间（每层 = 该层权重字节 ÷ 该设备有效服务带宽），不再混合。部分卸载场景误差从 43%/63% 降到 0%/8%。

**这条对预测的约束**：任何「部分卸载」的预测都必须逐层分开算再累加，把两端效率塞进一个系数是错的。离散 GPU 场景（4090）的卸载是带宽断崖（PCIe 30GB/s），机制不同，那条线仍走带宽模型，不走这个。
