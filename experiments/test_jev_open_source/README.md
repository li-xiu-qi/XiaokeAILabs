# Jev 系列开源复刻评测与复现实验

## 这个实验是什么

在智能体（Agent）和自动化工作流中，大量环节只需要做出快速路由、类别判定或状态评分（System 1 快速决策），并不需要大模型生成长文本。传统的自回归模型按 token 逐步生成，不仅延迟高，显存与计算成本也随着上下文和输出成倍增加。

TypeSafe 推出的 Jev 模型将判别式机制引入大模型，直接输出结构化概率，将决策延迟压缩到几十毫秒。但 Jev 官方仅提供云端商业接口且权重不公开。

本实验的核心目标，是对开源社区中出现的几种典型 Jev 复刻方案进行实机摸底，验证它们在本地单卡私有化部署下的工程可行性、性能上限以及在真实业务场景中的可用边界。

## 我们大概做了什么实验

我们选取了社区中技术路线各不相同的三个开源复刻项目，并引入主流轻量级生成式大模型作为基线对照：

- **Laya (1.1B)**：基于 ModernBERT 编码器加 Transformer 决策头的专用判别式架构，一次前向输出全部字段的概率，英文与多语言两个分支由路由器自动选择，支持单次请求合并多道题。
- **metask-jev (4B)**：基于 Qwen3.5-4B 微调，把候选答案约束为单个 Token，直接读取输出层对应 Token 的 Logits 并归一化为概率。
- **Nimble (9B)**：基于 Qwen3.5-9B 的 LoRA 适配器，配版本锁定的基座，在 CUDA 上用专用打分器逐字段计算。
- **Qwen3-VL (4B) 基线**：代表传统的自回归结构化（JSON）生成方案，作为延迟与成本的参照基准。

在统一的硬件平台（aarch64 架构、统一内存环境、单卡 CUDA）上，我们完成了以下四组核心实验：

1. **基准性能测量**：测试各模型在冷启动耗时、单次请求推理延迟（毫秒级中位数）以及常驻显存占用的真实表现。
2. **中英双语业务测试**：使用真实的工单分类与命题判定测试集（英文原文及严格对齐的中文场景），测试各模型在实际业务输入下的判定准确率与边界表现。
3. **特定运行机制验证**：深入实测 Laya 的多题合并批处理收益（计算摊薄效果）、中文命题判定中的概率校准表现，以及生成式方案因输出长度增加导致的耗时劣势。
4. **可复现日志归档**：所有实验运行均保存完整终端输出与硬件指标记录，数据与报告结论完全对应。
