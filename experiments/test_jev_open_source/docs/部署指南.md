# Jev 系列实验：部署指南

这份指南面向只想在本地部署一个 Jev 类模型、接入自己业务的人。不需要跑完全部四个模型，也不需要对齐报告里的数字。

想复现整套评测，看《复现教程.md》。各模型的延迟、准确率、显存实测，看《实验报告.md》。

## 先选模型

| 模型 | 参数 | 延迟（中位数） | 中文 | 常驻显存 |
|---|---|---|---|---|
| Laya | 1.1B | 16.98 ms（英文）/ 8.25 ms（中文） | 分类可用，命题判断失效 | 5.96 GB |
| metask-jev | 4B | 133.5 ms（英文）/ 133.7 ms（中文） | 分类 20/20 | 8.58 GB |
| Nimble | 9B | 365.33 ms（英文） | 上游声明仅英文，未测 | 17.57 GB |

只用英文、要最低延迟和最小显存，选 Laya。要中文分类，选 metask。字段数固定且业务只跑英文，才考虑 Nimble。

## 机器要求

带 NVIDIA 显卡的机器，x86_64 和 aarch64 都可以。显存按所选模型留，Laya 6 GB 起，metask 9 GB 起，Nimble 18 GB 起。磁盘只需要所选模型的权重，Laya 约 6 GB，metask 约 8.5 GB，Nimble 约 18 GB。不需要 root 权限，不依赖 Docker。

## 装环境

```bash
python -m venv /path/to/your-venv
source /path/to/your-venv/bin/activate

# 国内网络拉 Hugging Face 需要设置镜像端点
export HF_ENDPOINT=https://hf-mirror.com

pip install torch --index-url https://download.pytorch.org/whl/cu130
pip install transformers==5.16.1 accelerate peft==0.20.0 numpy
```

torch 与 transformers 的版本不必逐位对齐。注意 transformers 跨大版本时，Qwen3.5 系列的类名和模板行为会变，升级后先跑通自己的调用，再上线。

三个模型的部署步骤各自独立，按你选的那个读对应 README 即可，里面包含这条路线特有的步骤和坑：

|---|---|

## 验证部署成功

部署完用一条短输入验证模型能正常返回。对应模型的测试脚本里都有最小调用示例，跑通后能看到结构化的字段概率，而不是空输出或报错：

```bash
# 以 Laya 为例
python laya/laya-verify.py
```

## 生产环境注意事项

不要同时驻留多个模型，跑完一个释放显存，再加载下一个。显存预算按各模型的常驻值算，峰值会再高 0.1 到 0.5 GB。

输入长度直接影响单次前向耗时。本系列实测用的是 86 字符的短输入，真实业务输入更长，上线前用自己的真实数据测一遍延迟。

metask 的 `metask-temperature.json` 是上游拟合的置信度校准系数，输入分布和训练数据差得远时，建议用自己的数据重新校准，不要直接采信原始概率。
