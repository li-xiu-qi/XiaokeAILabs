# Jev 系列实验：复现教程

这份教程面向想在本地重跑整套评测、对齐《实验报告.md》数字的人。需要把四个模型全部跑一遍，合计下载约 36 GB 权重，请准备 60 GB 以上磁盘。

只想部署单个模型接入自己的业务，看《部署指南.md》，不需要跑这套流程。

## 环境与机器

机器要求、虚拟环境创建、依赖安装、镜像端点配置，和部署完全一致，见《部署指南.md》的「机器要求」和「装环境」两节，这里不重复。额外需要安装 Laya 的包：

```bash
pip install laya
```

## 四个模型的权重

| 路线 | 仓库 | 体积 | 前置步骤 |
|---|---|---|---|
| Laya | `convaiinnovations/laya` | 5.96 GB | 无，跑脚本时自动下载 |
| metask-jev-4B | `wayfind/metask-jev-4b-policy-mix` | 约 8.5 GB | 先跑 `metask-install.sh` |
| Nimble 9B | `bespokelabs/Bespoke-Nimble-9B` | 约 18 GB | 先克隆上游代码仓，再合成权重 |
| Qwen3-VL-4B | `Qwen/Qwen3-VL-4B` | 8.30 GB | 无，跑脚本时自动下载 |

建议一个一个拉，并发拉取容易被镜像站断流。断流后重跑即可，快照下载支持续传。

各模型的具体部署步骤见对应子目录的 README，也见《部署指南.md》的「部署单个模型」一节。

## 运行顺序

硬要求一条，先跑 Laya。20 条分类题和 5 条命题判断题是 Laya 定义的，其余三条路线照它的口径对齐，输入文本、任务定义、类别划分全部逐字一致。先跑别的，分不清数字差异来自模型还是来自口径。

```bash
python laya/laya-verify.py
python laya/laya-latency.py
python laya/laya-zh-en.py
```

Laya 跑完，另外三组没有先后顺序：

```bash
python nimble/nimble-deploy.py
python nimble/nimble-bench.py

bash metask/metask-install.sh
python metask/metask-bench.py

python llm_baseline/qwen4b-diag.py
python llm_baseline/qwen4b-latency.py
```

主脚本开头的注释写明了测什么、不测什么，跑之前可以先读一眼。

## 日志怎么读

每份日志按方括号分段，段首标号对应一个单独测量的量。以 `laya-latency.py` 为例，A 到 F 依次是冷启动、路由开销、单题前向、题数扩展、Router 与直连对比、资源占用。延迟要拆成多段看，合成一个数后无法定位开销来源。

分位数行给的最小值、中位数、九十分位、九十九分位、最大值要一起看。只看中位数会漏掉长尾，`laya-latency.py` 的最大值到过 2430 ms，那是首次调用的编译开销，不代表稳态。本报告引用的数字全部取中位数。

`^^` 开头的行是路由判定的实际落点和置信度，用来确认中文被分流到了多语言 checkpoint。路由分错，后面的延迟就没有意义。

## 结果对齐

跑完后，延迟中位数和准确率应该与《实验报告.md》的两张表一致。对不上时先查三件事：输入是否逐字一致、是否做了预热、依赖版本是否和实测组合（torch 2.14.0、transformers 5.16.1、laya 0.3.5）一致。
