# 数据格式性能模型

> 实证日期 2026-09-07 · Python 3.13.0 · 脚本 `scripts/data_format_model.py` · 结果公式自测通过

同一份数据在不同格式下的体积和速度可以闭式估算。本笔记给出 xlsx、sqlite、json、jsonl 四种格式的体积公式和读取延迟公式。详细实测数据见 `docs/数据格式体积与速度实测.md`（从 test_data_formats_bench 合并）。

## 体积公式

**xlsx**：zip 压缩的 XML，有共享字符串表。体积 ≈ (XML 体积 - 共享字符串节省) / 压缩率。XML 每单元格约 40 字节标签开销。重复值只存一次（共享字符串表）。

**sqlite**：不压缩的二进制行存储，每行约 20 字节开销。没有共享字符串表，重复值每行都存全量。体积 ≈ 行数 × (列数 × 值长 + 行开销)。

**json 行式**：每行一个对象，每单元格有键名 + 引号 + 冒号 + 逗号，约 12 字节开销。没有共享字符串表。体积 ≈ 行数 × (列数 × (键名开销 + 值长 + 标点) + 结构开销)。

**json 列式**：每列一个数组，键名只写一次。体积 ≈ 列数 × (键名 + 数组括号 + 行数 × 值长 + 标点)。比行式小约 40%（键名只写一次）。

**jsonl**：与 json 行式相同，只差外层数组括号换成换行符。体积 ≈ json 行式 × 1.0。

## 实测验证

用自制编码器验证（三种场景，2026-09-07）：

| 场景 | json 行式 实测/理论 | json 列式 实测/理论 | jsonl/json 行式 | 列式/行式 |
|---|---:|---:|---:|---:|
| 1 万行 10 列 基数 5 | 0.835 | 1.000 | 0.995 | 0.594 |
| 1 万行 10 列 基数 5000 | 0.835 | 1.000 | 0.995 | 0.594 |
| 5 万行 20 列 基数 5 | 0.855 | 1.000 | 0.998 | 0.583 |

json 列式与理论完全吻合（1.000）。json 行式和 jsonl 的理论值偏大（0.83-0.86），因为 Python 的 `json.dumps` 比理论公式更紧凑（不输出多余空格）。jsonl/json 行式比值 0.995-0.998，接近 1.0，验证了"jsonl 体积与 json 行式相同"的结论。列式/行式比值 0.58-0.59，验证了"列式比行式小约 40%"。

## 读取延迟公式

**xlsx 读取**：慢在 XML 解析，每单元格约 24 微秒。延迟 = 行数 × 列数 × 24 μs。百万单元格约 24 秒。

**json 读取**：一次 C 层扫描，延迟 = 文件大小 / 带宽（约 500 MB/s）。20 MB 文件约 40 毫秒。

**jsonl 全量读取**：比 json 慢 1.5-2.3 倍（逐行 `json.loads` 的固定开销）。

**jsonl 流式读取前 N 行**：与文件规模无关，约 5 微秒/行。读前 1000 行约 5 毫秒。

**json 追加一行**：必须读回整个文件、追加、整文件重写。延迟 = 2 × 文件大小 / 带宽。

**jsonl 追加一行**：只需在末尾追加，与文件规模无关，约 0.5 毫秒。

## 选型边界

- **反复读取、延迟敏感**：选 json（启动配置、索引、缓存）
- **长期归档、体积敏感、读取一次性**：选 xlsx
- **频繁追加、只读一部分**：选 jsonl（追加快 1000 倍，流式读快 100 倍）
- **跨进程反复查询结构化数据**：选 sqlite（落盘持久化）
- **列值高度重复**：最不该用 json（体积罚 3-6 倍），选 xlsx 或 sqlite

## 进阶优化

数据格式的优化围绕压缩、编码、序列化三个维度展开。

**压缩**：gzip（通用，压缩比 3-5x）、zstd（压缩比 4-8x，解压速度快）、LZ4（压缩比 2-3x，极快）。json 和 jsonl 都可以先压缩再落盘。xlsx 本身就是 zip 压缩。

**列式编码**：Parquet、ORC、Arrow。列式存储 + 压缩 + 谓词下推，比 json 快 10-50 倍。适合大数据分析。

**二进制序列化**：MessagePack（比 json 小 20-30%，解析快 2-3 倍）、Protocol Buffers（更紧凑，有 schema）、FlatBuffers（零拷贝）。适合高性能场景。

**增量编码**：Delta Encoding（差分编码）+ Varint，适合递增 ID 列表。倒排索引的 docID 列表标准做法。

**流式处理**：jsonl 天然支持流式读写，适合日志、事件流。json 全量形态不支持，必须先读完整文件。
