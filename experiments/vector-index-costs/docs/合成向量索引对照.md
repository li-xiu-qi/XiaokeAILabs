# 合成向量上的索引代价对照

本实验用同一批合成向量比较 Faiss 的精确搜索、分区、图和量化路径，观察召回、查询耗时和序列化体积如何变化。它用于理解索引参数的代价，不代表真实语义检索或生产服务的表现。真实文本向量的旧测另见 [README](../README.md)。

## 数据与测量

用 NumPy 种子 `20261107` 分别生成 20,000 条底库向量和 200 条查询向量，每条 128 维，元素独立服从标准正态分布；逐行 L2 归一化。查询与底库独立生成，数据不是文本编码的 Embedding。每种索引使用同一批向量与平方 L2 距离，Top-10 的精确结果由 `IndexFlatL2` 生成。召回率统计近似 Top-10 与精确 Top-10 的重合比例，结果并列时按 Faiss 返回的 ID 计算。

本次在 Windows 11 x64、Python 3.13.0、NumPy 2.5.4、Faiss CPU 1.13.2、单线程运行。每个配置单独构建；索引训练与添加合并计时。每项先预热 8 条查询，再对完整 200 条查询批量搜索 3 次，取批总耗时中位数除以 200。体积是 `faiss.serialize_index` 的输出大小，不包含进程开销和查询时工作区，不等于峰值内存。各组索引都在同一进程依次运行，计时会受系统活动与缓存状态影响。

## 探索范围如何影响召回

| 索引 | 关键参数 | Recall@10 | 批平均耗时 ms/查询 | 序列化字节 |
|---|---|---:|---:|---:|
| Flat | 全量精确 | 1.0000 | 0.0688 | 10,240,045 |
| IVF-Flat | nlist 64，nprobe 4 | 0.2150 | 0.0669 | 10,433,419 |
| IVF-Flat | nlist 64，nprobe 16 | 0.5520 | 0.2385 | 10,433,419 |
| IVF-Flat | nlist 64，nprobe 32 | 0.8040 | 0.2576 | 10,433,419 |
| HNSW-Flat | M 16，efSearch 16 | 0.2185 | 0.0665 | 13,123,834 |
| HNSW-Flat | M 16，efSearch 64 | 0.5290 | 0.2969 | 13,123,834 |
| HNSW-Flat | M 16，efSearch 128 | 0.7395 | 0.3857 | 13,123,834 |

本次扩大 IVF 搜索分区或 HNSW 探索范围时，召回随之上升，耗时也增加。即便探索范围增加到表中最高值，随机向量上的召回仍不足 0.81。这个数据分布和规模下，低召回方案即使耗时接近 Flat，也不能作为同等质量的加速方案。

参数扫描每个取值都重新构建索引，测量受构建随机性、系统负载与缓存影响。每组只有三次查询计时，IVF 的 32 个分区三次总耗时波动约 38.5 至 81.2 毫秒；表中数值不适合用来判断微小性能差异，也不代表单请求 P50/P99。原始三次计时保留在[证据文件](../evidence/synthetic_n20000_d128_20261107.json)。

## 压缩省了多少空间，损失了多少近邻

| 索引 | 关键参数 | Recall@10 | 批平均耗时 ms/查询 | 序列化字节 |
|---|---|---:|---:|---:|
| Flat | float32 原始向量 | 1.0000 | 0.0688 | 10,240,045 |
| SQ8 | 每维 8 bit | 0.9830 | 0.4111 | 2,561,105 |
| PQ | 8 个子空间，每个 8 bit | 0.1005 | 0.0963 | 291,158 |
| IVF-PQ | nlist 64，nprobe 4，PQ 8×8 bit | 0.0720 | 0.0182 | 484,532 |
| IVF-PQ | nlist 64，nprobe 16，PQ 8×8 bit | 0.1115 | 0.0824 | 484,532 |
| IVF-PQ | nlist 64，nprobe 32，PQ 8×8 bit | 0.1200 | 0.0998 | 484,532 |

PQ 主体编码及码本使序列化体积降到 Flat 的约 2.8%，但本次精确近邻召回也降到 0.1005。IVF-PQ 增加分区和 ID 后比 PQ 多占空间，`nprobe` 从 4 增至 32 带来召回增长，但仍不能解决压缩造成的排名误差。SQ8 保留较高召回，但本次批量搜索比 Flat 慢。这些数字说明应该同时测量空间、速度和质量，不能仅凭编码长度推断速度或效果。

空间公式和检索路径见[原理与选型](索引原理与选型.md)。这些序列化数字不含保留原始向量进行重排所需的额外空间，也不等于系统中的运行内存。

## 运行

用 Python 3.13 新建隔离环境，安装依赖后从实验目录运行：

```bash
python -m pip install faiss-cpu==1.13.2 numpy==2.5.4
python scripts/benchmark_synthetic.py --out /tmp/vector-index-synthetic.json
```

Windows 用户可将输出路径换成本机临时目录。脚本重建向量和每个索引，不下载模型或真实语料，生成的 JSON 含完整配置、参数、构建时间、三次批量计时及字节数。不同 CPU、系统负载或 Faiss 版本下耗时不应期待完全一致。

## 口径与边界

本次按固定随机种子生成单位球面上近似均匀的向量；真实文本向量的聚集、重复、尾部密度和查询分布可能完全不同。没有测并发、过滤、更新、GPU、持久化读写、进程 RSS 或峰值内存；也没有给不同索引调到相同召回水平。实验结果不能直接决定线上参数。
