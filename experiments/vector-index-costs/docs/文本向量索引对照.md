# 文本向量上的索引对照

本记录复用一份已有的 20 Newsgroups 文本向量，对统一内积度量的 Flat、HNSW、IVF、SQ 和 PQ 进行对照。它展示同一份向量如何用于索引比较，不测 Embedding 模型的文本相关性，也不能作为生产延迟指标。

## 数据和方法

输入 NPZ 包含 11,293 条底库向量与 600 条查询向量，每条 384 维。已有记录标注向量由 `all-MiniLM-L6-v2` 对 20 Newsgroups 编码，但未保留模型 revision 和编码脚本，无法独立核实具体版本；NPZ 的 SHA-256 为 `c1cf26f1943037b80407f26e31649af4410fb42c021582323fcaf7cbae147ec7`。数据不随仓库分发。

转换脚本对输入向量逐行做 L2 归一化；测量脚本直接读取转换后的向量，以 Flat 内积搜索生成 Top-10 对照，所有被测索引显式使用内积。若直接提供其他 float32 文件，测量脚本不会代为归一化，应自行核对数据与元信息。单线程 Faiss CPU 1.13.2、NumPy 2.5.4，Windows 11 x64。每个索引构建一次，对完整 600 条查询批量运行三次，先预热 8 条；下表耗时取三次批量总耗时的中位数除以 600。各配置独立建索引，构建时间不进入查询计时。

## 结果

| 索引 | 参数 | 近邻 Recall@10 | 批平均耗时 ms/查询 |
|---|---|---:|---:|
| Flat | 精确内积 | 1.0000 | 0.0715 |
| IVF-Flat | nlist 1024，nprobe 8 | 0.8180 | 0.0245 |
| IVF-Flat | nlist 1024，nprobe 32 | 0.9555 | 0.0626 |
| HNSW-Flat | M 16，efConstruction 64，efSearch 16 | 0.9342 | 0.0384 |
| HNSW-Flat | M 16，efConstruction 64，efSearch 64 | 0.9923 | 0.1099 |
| SQ8 | 8 bit/维 | 0.9948 | 0.8191 |
| PQ | 32 子空间，8 bit/子空间 | 0.6200 | 0.1334 |
| IVF-PQ | nlist 1024，nprobe 8，PQ 32×8 bit | 0.6332 | 0.0242 |

IVF 和 HNSW 在搜索参数较大的配置下测得较高近邻召回；由于每个配置单独训练或构建索引，索引本身的差异也可能影响结果。要单独考察参数作用，应固定已构建索引再逐档查询，并重复构建与计时。SQ8 保留了较高召回，却比 Flat 慢；PQ 和 IVF-PQ 则在各自配置下损失更多近邻。不同召回率的延迟不能直接用作等质量排名。

查询计时波动明显：例如 HNSW 的 `efSearch=32` 三次批量耗时约为 41、82、145 毫秒。表中中位数不是单次请求延迟，也不能据此推断细小差异。全部参数、构建时间与逐次批量耗时见[实测证据](../evidence/real_corpus_ip_20261107.json)。

## 值得留意的限制

Faiss 对 IVF 的 1,024 个中心给出训练样本不足警告：11,293 条低于其建议的 39,936 条。参数选择延续这组旧测用于对照，不表示它适合这一规模，更不代表聚类质量已经充分。训练和索引共用底库向量，仅查询留出，未测数据分布迁移。结果的召回是对精确向量近邻的还原，不代表文档与用户问题之间的语义相关性。

原始文本与模型版本无法由 NPZ 重建，精确复现需要同一份向量文件。若使用自己的可信 NPZ 数据，请参考 [README 的命令](../README.md#如何动手)，并记录编码模型版本、文本切分与向量来源。另有独立可重建的[合成向量实验](合成向量索引对照.md)，可用于验证脚本与索引机制。

脚本固定扫描 `nlist=1024`、PQ `m=32`：输入至少需要 1,024 条底库向量，维度必须能被 32 整除；满足最低数量也不代表聚类训练样本充分。若输入不满足，应重新设计参数并在报告中说明，不可直接对照表格。
