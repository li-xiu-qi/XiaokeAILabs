# 文档 OCR 与解析实验

一份扫描文档不仅需要识别文字，还可能包含多栏阅读顺序、公式和表格。这个系列关注如何把图像或 PDF 转成可用内容，以及如何检查解析结果。各实验分别说明模型、数据和运行环境；目前尚不能据此比较不同方案的识别准确率。

## 两种处理路径

**生成式文档解析**使用视觉语言模型读取图像内容并生成文本或结构化结果，例如 Markdown。实际系统仍可先用布局模型划分页面，再逐块调用生成模型；因此“生成式”描述的是内容生成方式，不代表整条流程一定只有一个模型。MiniCPM-OCR 实验包含布局检测、区域识别及结果组装，详见其运行配置。

**分模块管线**可将页面依次送入布局分析、文字检测、文字识别和表格结构识别等模块，再把文字与单元格关系组装成结果。不同文档类型可选择不同模块；例如 PaddleOCR 的 PP-StructureV3 支持布局分析、通用 OCR、表格识别和公式识别等组件。分模块输出有助于定位错误发生在哪一步，但需要分别配置模型和处理模块之间的数据。

两条路径可以组合：先用布局检测确定区域，再使用生成模型解析；也可以把多个解析结果交给质量模型辅助筛查。具体效果取决于文档、模型、运行环境和评价方式，不能仅凭架构断言谁更准确或更快。

## 如何评价结果

MiniCPM-OCR Jev 对原始区域图、候选内容及其渲染图输出一致性分数，可用于候选排序或辅助抽查。**分数不是识别准确率，也不能直接当作正确概率**；要用于自动通过或转人工审核，需要在目标文档上收集人工标注，检验阈值下的误判、通过率与校准情况。模型用法见 [OpenBMB 官方说明](https://github.com/OpenBMB/MiniCPM-OCR/blob/main/docs/minicpm_ocr_jev_en.md)。

后续对比应固定输入文档和数据划分，分别记录文字错误、表格结构、阅读顺序、耗时与资源占用，并保留原始输出及评估脚本。当前系列尚无这种跨方案统一评测，因此不提供排名。
