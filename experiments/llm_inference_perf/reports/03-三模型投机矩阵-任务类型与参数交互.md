# 三模型 × 五投机配置全矩阵：任务类型才是收益的第一变量

本报告为该实验序列的第二阶段，用**统一口径的三任务矩阵**重测此前分散得出的结论。前序两份参数扫描与综合报告各自只用了固定单一提示词，本阶段把「任务类型」显式设为自变量后，前一阶段的两条核心结论被推翻。完整修订后的结论以本报告为准，《投机解码收益的机制条件》中未与本报告冲突的部分仍然有效。

## 实验设计与口径

### 为什么要重测

前序实验的关键缺陷是**只用一个提示词**。综合报告的「MoE 上挂 MTP 零收益」结论，来自一个约 28 token 的自由生成提示词；35B-A3B 的 +18.9% 与 +43.5% 来自另一个提示词；两组的矛盾被归因到「激活参数量与草稿参数量的比例」，但任务内容这个更直接的变量从未被控制。

矩阵法把任务类型变成显式自变量：同一模型、同一服务参数、同一构建下，跨三种任务各测三轮，看收益如何随任务变化。

### 三个任务

| 任务 | 性质 | 输入长度 | 输出与输入的关系 |
|---|---|---:|---|
| T1 自由生成 | 从零写一段约 300 字介绍 | 28 token | 输出词汇与输入几乎无重合 |
| T2 长文本改写 | 把技术说明改写成通俗版，**保持所有数字、产品名、结论不变** | 276 token | 输出大量复用输入词汇 |
| T3 代码改写 | 补全类型注解 + 抽公共错误处理，**保持行为完全一致** | 约 250 token | 输出大量复用输入标识符与结构 |

这个设计让「输出对输入的依赖强度」从弱到强形成梯度，是解释后文全部结果的关键。

### 统一服务参数

除投机配置本身外，三轮测试的主模型服务参数逐字一致：

```
-ngl 99 -c <模型满档上下文> -np 1 -t 8
--cache-type-k q8_0 --cache-type-v q8_0
--host 0.0.0.0 --port 8835 --jinja
```

测量走 `/completion` 端点，`n_predict=400` + `ignore_eos` 固定输出长度，每配置每任务**连续三轮**（前序实验证明单轮测量会让结论方向出错，同配置三轮极差可达 14%）。每配置切换前有暖机请求，结果不计入统计。所有测试在 DGX Spark 上完成，构建锁定 commit `a0e6dc7`（build 792），单机独占。

## 发现一：任务类型是第一变量，模型结构是第二变量

三模型 × 三任务的加速比矩阵（相对各自基线）：

| 模型 | T1 自由生成 | T2 长文本改写 | T3 代码改写 |
|---|---:|---:|---:|
| 125B MoE（MTP 最优档） | +16.4% | +31.8% | +57.0% |
| 27B 稠密（DFlash2） | +54.3% | +133.3% | +131.4% |
| 35B-A3B MoE（MTP） | +40.7% | +33.5% | +44.8% |

两点直接读出来的事实：

**同一任务下，稠密模型的收益远高于 MoE**。27B 稠密在 T2/T3 上跑到 2.33 倍，125B MoE 在同样任务上只有 1.32 至 1.57 倍。这与前一阶段的判断方向一致：稠密模型每步必须搬完整份权重，批量验证能把这份搬移摊薄；MoE 每步只搬激活的专家，摊薄的基数本来就小。

**同一模型下，改写类任务的收益高于自由生成**。三个模型全部符合，无一例外。125B 从 +16.4% 抬到 +57.0%，27B 从 +54.3% 抬到 +131.4%。

### 为什么改写的收益更高：每轮前向的产出 token 数

用 125B 的 MTP 组做算术。生成 400 token，记录草稿数与接受数，可推出主模型实际执行的前向次数：`前向次数 = 生成数 − 接受数`。

| 任务 | 草稿数 | 接受数 | 接受率 | 前向次数 | 每前向产出 token |
|---|---:|---:|---:|---:|---:|
| T1 自由生成 | 229 | 192 | 83.8% | 208 | 1.92 |
| T2 长文本改写 | 254 | 237 | 93.3% | 163 | 2.45 |

T2 每次主模型前向产出 2.45 个 token，T1 只有 1.92 个，差 28%。这是收益差的直接来源。

而接受率的高低的根源在任务本身：T2 要求「保持所有数字、产品名和结论不变」，模型输出要大量复用输入词汇；T1 是从零写一段新内容，没有任何可复用的既有序列。草稿模型（无论 MTP 还是 DFlash2）本质是在预测「下一个 token 是什么」，当答案高度受输入约束时，预测难度大幅下降。

**接受率不是收益的同义词**。下表是 125B 三组 MTP 的对照，接受率与吞吐呈反向：

| 配置 | T1 接受率 | T1 草稿数 | T1 吞吐 |
|---|---:|---:|---:|
| n3-p0 | 54.3% | 1366 | **42.94** |
| n3-p0.75 | 84.3% | 783 | 39.53 |
| n5-p0 | 32.9% | 2266 | 32.52 |

n3-p0 的接受率比 n3-p075 低 30 个百分点，吞吐反而高 8.6%。机制是 `p_min=0.75` 会在草稿置信度不足时提前掐断投机链，草稿总数从 1366 掉到 783（少 43%），虽然每一个投出去的猜测更容易被接受，但每轮喂给主模型的候选变少，主模型一次前向摊薄的收益随之缩小。**真正决定收益的是每轮前向的产出 token 数，接受率只是它的一个中间变量。**

## 发现二：p_min 的最优值此前测反了

前序综合报告载明的结论是：对同源 MTP 草稿头，「过滤低置信度猜测是净赚」。本轮在 `n_max=3` 固定下做了 p_min 的两点对照：

| 任务 | p_min=0.0 | p_min=0.75 | 差 |
|---|---:|---:|---:|
| T1 自由生成 | 42.94 | 39.53 | **−8.0%** |
| T2 长文本改写 | 48.31 | 47.89 | −0.9% |
| T3 代码改写 | 57.52 | 53.21 | −7.5% |

**p_min=0.0 在三个任务上全面不劣于 p_min=0.75**，两个任务上明显更优。35B-A3B 的同向对照见下方补充轮次（四组档位全部同向），27B 的 DFlash2 对照亦同向。前一阶段的判断基于一个只看接受率、没看吞吐的对照（p_min 从 0 调到 0.75 时接受率从 38.57% 抬到 78.7%），把「接受率上升」直接当成了「机制变好」。矩阵数据表明这个推论不成立。

对 DFlash2 的结论方向不变（p_min=0 明显更优，前一阶段已测得 23.34 vs 17.16）。修正后的统一表述是：**两类草稿模型都应留 p_min=0.0，让草稿跑到 n_max 上限**，而非按草稿来源区别对待。

## 发现三：n_max 有明确上限，超过 3 转为负收益

125B 上固定 p_min=0.0，扫 n_max 三档：

| 任务 | n_max=3 | n_max=5 | 差 |
|---|---:|---:|---:|
| T1 自由生成 | 42.94 | 32.52 | **−24.3%** |
| T2 长文本改写 | 48.31 | 44.89 | −7.1% |
| T3 代码改写 | 57.52 | 54.93 | −4.5% |

n_max=5 时草稿数从 1366 涨到 2266（多 66%），接受率从 54.3% 塌到 32.9%，净效果是三个任务全部下降。推测深度越深，草稿累积误差越大，一旦主模型在前段拒绝，后续草稿全部作废。自由生成任务对误差最敏感（−24.3%），代码改写最不敏感（−4.5%，因其输出受输入强约束、草稿不易跑偏）。

综合本轮与前一阶段的数据，**125B MoE + MTP 的推荐参数是 `n_max=3, p_min=0.0`**；27B 稠密 + DFlash2 在 n_max=3 上也取到全矩阵最优。

### 35B-A3B 的 MTP 参数对照（补充轮次）

主模型 C 的内置 MTP 头在四个参数档位下的实测（基线 64.07 / 65.29 / 65.13，括号内为三轮标准差）：

| 配置 | T1 自由生成 | T2 长文本改写 | T3 代码改写 |
|---|---:|---:|---:|
| mtp n2, p_min=0.0 | 82.07 (3.34) | 86.80 (4.90) | 99.19 (6.74) |
| mtp n2, p_min=0.75 | 74.14 (2.21) | 73.48 (1.05) | 89.39 (2.00) |
| mtp n3, p_min=0.0 | 76.87 (9.14) | 85.51 (4.86) | **109.29 (0.82)** |
| mtp n3 + backend-sampling | 85.42 (0.59) | 85.30 (5.02) | 97.94 (5.44) |

三点：

**p_min=0.75 再次全面劣于 0.0**，与 125B 和 27B 的结论完全一致。至此三个模型、四组 p_min 对照的证据同向，`p_min` 留 0.0 这条可以当作跨模型稳健结论使用。

**n_max 的上限随模型不同**。125B 上 n_max=3 最优、5 转负；35B-A3B 的 n_max=3 在代码改写上拿到全表最高的 109.29（相对基线 +67.8%），未出现衰减。激活量更小的模型草稿头更轻，能承受更深的推测。此前「125B 上 n_max=3 最优」不能直接外推到其他模型。

**35B-A3B 是三个模型里任务敏感性最低的**（三个任务最低 +15.7%、最高 +67.8%，全部大幅正收益），与它的草稿头内置于主模型、额外开销极小相符。对照 125B 的 MTP 草稿头是 3.85 GiB 独立文件，同一件事在 125B 上就要打折。

`--spec-draft-backend-sampling` 在 T1 上表现最好（85.42，标准差仅 0.59），T3 略低于不带该开关的 n3（97.94 对 109.29）；本阶段未做该开关的专项对照，不足以给出推荐与否的结论，留作后续。

## 发现四：N-gram 系列在三种任务、三个模型上全部失效

`ngram-simple` / `ngram-map-k` / `ngram-mod` 三种 n-gram 投机共 9 组配置 × 3 任务 × 3 轮，结果无一组产生可复现的正收益：

| 模型 | ngram-simple（T1/T2/T3） | ngram-map-k | ngram-mod |
|---|---|---|---|
| 125B | 35.98 / 34.93 / 30.29 | 33.85 / 32.89 / 32.11 | 35.24 / 33.04 / 33.06 |
| 27B | 12.45 / 12.43 / 12.45 | 14.34 / 12.39 / 12.64 | 12.59 / 13.36 / 12.62 |
| 35B-A3B | 61.44 / 66.06 / 61.76 | 69.06 / 60.10 / 56.62 | 59.27 / 56.95 / 58.55 |

对照各自基线（36.6 / 12.76 / 65.1），绝大多数格低于基线，少数几格（35B-A3B 的 ngram-map-k T1 = 69.06）高于基线但标准差达 11.07，不可信。

唯一出现的 100% 接受率（125B 与 27B 的 ngram-map-k T1 各 144 个草稿全部接受）也没有换来吞吐，因为草稿总量只有 144，相对 1200 个生成 token 占比过低，摊薄效果可忽略。

### 为什么 n-gram 在改写任务上也失效

直觉上 T2/T3 要求「保持数字、产品名不变」「保持行为一致」，输出应当大量重复输入序列，正是 n-gram 投机的理想场景。实测接受率却只有 5% 至 7%。原因在于 n-gram 投机要求的是**连续 token 序列的精确复现**，而改写任务的输出虽然复用了词汇与标识符，语序、句式与插入位置都已改变：

- T2 要把技术说明改写成「面向普通读者的通俗版本」，每个句子都重写，只有数字与产品名保持逐字一致，而这些短片段之间被新写的自然语言隔开，形不成足够长的连续 n-gram。
- T3 要给每个函数参数补类型注解，`def load_config(path):` 变成 `def load_config(path: str) -> dict:`，恰好打断了原本连续的代码序列；错误处理抽取还会重排函数体顺序。

**n-gram 投机适用的是「大段原样复制」的场景**（检索增强的原文引用、代码补全中重复既有行、格式转换中照搬字段），不是「改写」。本轮任务的失败与该机制的适用边界一致，不构成对其价值的否定。

## 机制解释与待验证假设

本轮数据支持一个统一框架：**投机的净收益 = 每轮前向多产出的 token 数所带来的时间节省 − 草稿模型自身前向的开销**。

三个模型在这两项上的位置不同：

| 模型 | 批量验证的摊薄效果 | 草稿开销占比 | 净收益 |
|---|---|---|---|
| 27B 稠密 | 大（每步搬全量 15.33 GiB，验证 2 至 3 个 token 时权重可复用） | 小（草稿 1.06 GiB，约主模型 7%） | 最高，2.33× |
| 35B-A3B MoE | 中 | 很小（MTP 头内置于主模型） | 中高，+34~45% |
| 125B MoE | 小（单步激活 6B，摊薄基数小） | 大（草稿 3.85 GiB，接近主模型单步激活量） | 最低，+16~57% |

为什么 MoE 的「批量验证摊薄」效果比稠密差，一个待验证的假设是**专家分散**：MoE 每步只激活少数专家，批量验证 n 个 token 时，这 n 个 token 各自激活的专家集合未必相同，若分散则需要搬移更多专家的权重，带宽开销接近随 n 线性增长；稠密模型无论验证几个 token，搬的都是同一份权重，GEMM 批处理可以充分复用。

125B 的专家总数多于 35B-A3B，分散概率更高，这与「125B 收益低于 35B-A3B」的实测方向一致。此假设未被直接测量（需要专家命中率或权重搬运量的细粒度统计），列为后续实验方向。

## 对前序结论的修订

综合报告与两份参数扫描中的以下表述**在本报告实测范围内不成立**，以本报告为准：

| 前序表述 | 修订后 |
|---|---|
| MoE 稀疏激活模型挂草稿模型反而净亏 | 不成立。125B MoE 在最优参数下有 +16.4% 至 +57.0% 的正收益 |
| 125B MoE 上挂 MTP 生成吞吐零收益 | 不成立。零收益是「`n_max=2` + `p_min=0.75` + 单一自由生成提示词」这组特定条件下的结果，被错误泛化为模型级结论 |
| 对同源 MTP 草稿头，过滤低置信度猜测是净赚 | 方向相反。`p_min=0.0` 在三个任务上全面不劣于 `p_min=0.75`，两处明显更优 |
| 高接受率无法转化为吞吐收益是 MoE 的特性 | 部分成立但归因偏了。低 p_min 高接受率同样换不来吞吐，真正的决定量是每轮前向的产出 token 数，与模型结构无关 |

仍然成立的部分：稠密模型是投机解码的理想受益对象；引擎构建版本是强干扰变量、A/B 必须锁同一构建；`-np 1` 是投机服务的硬约束；prefill 端存在可重复的损失。

## 适用边界

本报告结论在以下边界内成立：

- 单请求串行（`-np 1`），无外部并发竞争。
- 每配置每任务三轮取均值；标准差已在表中列出，差异小于标准差量级的格不作断言。
- 构建锁定 commit `a0e6dc7`（build 792），跨构建的绝对数值不可直接拼接。
- 主模型量化分别为 IQ4_XS / UD-Q4_K_M，草稿模型 Q8_0 / Q4_K_M，KV 缓存 q8_0。
- 统一内存架构（GB10），与离散显卡的通信开销模型不同。
- 三个任务各只有一个提示词，同一任务类型的提示词间差异未测。这是本阶段矩阵法的主要局限。

## 未覆盖范围

- 同一任务类型下换提示词，验证任务类型效应的稳定性（当前每类只有一题）。
- 35B-A3B 的 n_max 与 p_min 扫描（本阶段只用内置默认）。
- 长上下文（4K 到 256K）下投机加速比的衰减曲线。
- 多用户并发交错请求下与连续批处理的兼容性。
- 专家分散假设的直接验证（专家命中率 / 权重搬运量统计）。
- 其他草稿机制：Medusa 多头推测、基于层跳跃的草稿。
