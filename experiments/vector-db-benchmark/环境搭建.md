# 向量检索基准：环境与运行说明

这份说明解释如何准备本实验的六种数据库，以及脚本实际测量的范围。建议先使用 sqlite-vec 的合成数据检查安装，再准备真实文本向量，最后逐项启动需要的服务。合成数据只用来检查流程，不用于推断数据库在真实检索中的性能。

**请使用独立的测试实例和数据目录。** `index_bench.py` 使用本次独立命名的集合或路径，并尝试清理本次创建的对象，失败时仍可能有残留；这一改动尚未通过真实数据库验证。其他历史脚本仍可能删除固定名称的集合或路径，不要将其指向含有其他数据的服务或目录。默认服务地址写在 `scripts/index_bench.py` 文件顶部。

含固定对象删除操作的历史基准和探针默认拒绝执行，包括 `bench.py`、`multi_bench.py`、`final_bench.py`、`hybrid_search_bench.py`、`memory_surreal.py`、`smoke_test.py` 及相关 `probe_*.py`；确认已使用专用空实例和隔离数据目录后，需设置 `XL_VECTOR_DB_ALLOW_DESTRUCTIVE=isolated-instance` 才能运行。该设置只是操作者的确认，不能自动隔离数据或避免误删；`index_bench.py` 不需要此设置。

## 1. 安装与冒烟检查

以下命令从本实验目录的 PowerShell 运行，需要一个支持扩展加载的 Windows Python 环境。先仅安装 sqlite-vec 路径需要的依赖：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install numpy==2.5.2 sqlite-vec==0.1.9
New-Item -ItemType Directory -Force data | Out-Null
.\.venv\Scripts\python.exe scripts/index_bench.py --only sqlite --synthetic --efs 64 --rounds 2
```

此路径的历史版本曾在 Windows、Python 3.13.0、NumPy 2.5.2 和 sqlite-vec 0.1.9 下以隔离副本运行；加入隔离保护后的脚本尚未实际复跑。合成模式生成 30,000 个 768 维随机向量及 50 个查询，以平方欧氏距离的精确 top-10 作为参照。历史冒烟的 Recall@10 为 1.0，只表明该样例中 sqlite-vec 查询结果与脚本计算的精确邻居一致，不代表真实数据或其他数据库的表现。

输出保存在 `results/indexbench-synthetic-30k-d768-<时间>.json`。检查对应条目是否含 `error`，并查看终端是否出现 `FAILED`：脚本会捕获单个配置的异常并继续运行，进程正常退出本身不表示每个配置都成功。脚本将首轮作为预热，延迟统计只使用后续轮次，`--rounds` 至少取 2。

## 2. 准备真实文本向量

按照 [README 的数据准备步骤](README.md#1-准备-python数据和模型)下载 20 Newsgroups 和 all-MiniLM-L6-v2，执行 `scripts/gen_emb.py`。该脚本只读取实验目录下 `models/all-MiniLM-L6-v2/` 的本地模型，不会自动下载；它清理邮件头、过滤短文本并截断正文，再把 train 和 test 分开编码到 `data/20news_emb.npz`。

随后可运行：

```powershell
.\.venv\Scripts\python.exe scripts/index_bench.py --only sqlite
```

请同时保留数据来源、模型 revision、文件校验值、软件版本、命令与输出 JSON。向量生成路径尚未在本轮重新完整安装并运行，重新下载的模型或依赖变化可能影响结果。历史记录中的文档数量只是当次结果，实际数量以生成文件为准。

## 3. 选择其他数据库

以下是仓内适配器使用的部署形态和连接方式。服务版本、Python 客户端及索引能力需要一起匹配；`requirements.txt` 是历史依赖清单，不保证对每个新系统都可安装或兼容。

| 选项 | 运行方式 | 脚本连接或数据位置 |
|---|---|---|
| `milvus` | 独立服务，历史实验使用 Docker Compose | `127.0.0.1:19530`；存储测量依赖 `config/volumes/minio` 路径 |
| `qdrant` | 独立服务，历史实验使用 Docker | `127.0.0.1:6333`；存储测量依赖 `data/qdrant/collections` |
| `surreal` | Windows 原生服务，由脚本逐轮启动 | 需要 `bin/surreal.exe`；端口从 8100 开始 |
| `lance`、`chroma`、`sqlite` | 嵌入式 Python 库 | 实验目录下 `data/` 中的各自测试路径 |

Milvus 的仓内 Compose 文件保留了历史实验配置，不要用在线 `master` 文件覆盖它并声称复现了相同环境。新建独立部署可参考 [Milvus 官方 Compose 指南](https://milvus.io/docs/install_standalone-windows.md)；Qdrant 可参考[官方本地部署指南](https://qdrant.tech/documentation/quickstart/)。升级服务或使用不同版本后，需要重新检查适配器 API、索引和数据目录，历史结果不能直接与新环境混用。

下面按目标库单独准备；命令沿用第 1 节的 PowerShell 和 `.venv`。历史清单中的客户端版本是起点，不代表已验证与当前系统及服务兼容。

### Milvus

安装 Docker Desktop、Compose 并启动 Docker；确认 19530、9091、9000、9001 端口空闲，仓内 Compose 使用固定容器名和 `config/volumes/`，不要与已有部署共用。以下会下载镜像并启动三个服务：

```powershell
.\.venv\Scripts\python.exe -m pip install pymilvus==3.0.1
docker compose -f config/milvus-standalone-compose.yml up -d
docker compose -f config/milvus-standalone-compose.yml ps
Invoke-WebRequest http://127.0.0.1:9091/healthz
.\.venv\Scripts\python.exe -c "from pymilvus import MilvusClient; print(MilvusClient(uri='http://127.0.0.1:19530').list_collections())"
```

等待容器健康检查通过；客户端列出集合表明可以连接，但不证明所有索引适配器可用。Compose 包含默认测试凭据，只用于隔离测试。该服务组合和命令未在本轮端到端重跑。

### Qdrant

Docker 运行时需允许绑定本实验目录；空闲的 6333 端口供客户端使用。下面把服务数据挂载到脚本读取存储大小的位置：

```powershell
.\.venv\Scripts\python.exe -m pip install qdrant-client==1.19.0
New-Item -ItemType Directory -Force data/qdrant | Out-Null
$qdrantData = (Resolve-Path data/qdrant).Path
docker run -d --name vector-bench-qdrant -p 127.0.0.1:6333:6333 --mount "type=bind,source=$qdrantData,target=/qdrant/storage" qdrant/qdrant
Invoke-RestMethod http://127.0.0.1:6333/
.\.venv\Scripts\python.exe -c "from qdrant_client import QdrantClient; print(QdrantClient(url='http://127.0.0.1:6333').get_collections())"
```

示例镜像未固定标签，需记录 `docker image inspect qdrant/qdrant` 输出中的镜像 ID；服务和客户端的组合未在本轮端到端重跑。部分 Windows 文件系统不适合绑定挂载，替换挂载方式时存储体积测量路径也必须随之核对。

### SurrealDB、LanceDB 和 Chroma

SurrealDB 适配器仅使用 Windows 可执行文件，按 [SurrealDB 安装说明](https://surrealdb.com/install)取得兼容的 Windows 版本后放在 `bin/surreal.exe`。脚本会为每组配置从 8100 起启动独立进程，无需预先启动服务，确保对应端口空闲。LanceDB 和 Chroma 使用嵌入式库，无需 Docker：

```powershell
.\.venv\Scripts\python.exe -m pip install surrealdb==1.0.4 psutil lancedb==0.38.0 chromadb==1.5.9
.\bin\surreal.exe version
.\.venv\Scripts\python.exe -c "import surrealdb, psutil, lancedb, chromadb; print('psutil', psutil.__version__, 'lancedb', lancedb.__version__, 'chromadb', chromadb.__version__)"
```

以上检查仅确认可执行文件或模块可以运行和导入；SurrealDB 实际启动、连接和各库索引能力仍需在隔离目录运行相应基准验证。这些客户端和服务的组合尚未在本轮完整重跑，遇到 API 或安装问题须核对相互兼容的版本。

其他探针按需安装：`probe_jieba_tokenizer.py` 需要 `jieba`，图表脚本需要 `matplotlib`。`probe_vikingdb.py` 依赖 OpenViking 及其本地向量扩展，历史使用独立环境，仓库未锁定可重建的版本和编译配置；需先按上游项目说明安装并确认导入。该脚本会删除并重建 `data/viking_probe` 与 `data/viking_cn`，中文部分还需要与向量同序的 `data/20news_texts.npz`，运行前应使用隔离的实验副本。图表脚本的历史硬编码数据不代表新运行结果。

装好目标库依赖并确认隔离服务就绪后，通过 `--only` 缩小范围：

```powershell
.\.venv\Scripts\python.exe scripts/index_bench.py --only qdrant --index HNSW
```

`--index` 仅运行该库适配器中声明的同名索引；没有匹配项时会跳过。`--efs` 的数值会被不同索引映射为不同查询参数，不能假定它们具有相同含义。新输出的 `version` 为 null；`adapter_version_hint` 是历史硬编码标签，不是检测到的版本，须另行记录客户端和服务的真实版本。旧结果中的 `version` 也不能作为版本证据。

## 4. 数据与指标边界

脚本从 test 划分按类别采样查询，每个查询的精确 top-10 与数据库返回的 ID 集合求交。这个 Recall@10 度量索引相对精确向量搜索找回了多少近邻，不衡量这些近邻是否回答用户问题。延迟为单条查询的客户端计时，默认首轮预热、后两轮汇总 p50 和 p95，不是并发吞吐。

脚本记录写入、建索引及文件大小增量，但服务的存储位置、预分配和异步落盘方式不同；若没有统一快照和依赖服务的统计边界，不能据此比较各产品总存储。`--text-storage` 还要求与向量严格同序的 `data/20news_texts.npz`；运行 `scripts/gen_emb.py --texts-output data/20news_texts.npz` 可在生成向量时一并生成文本，两文件会在运行前检查摘要和行数。历史向量缺少正文摘要，不能据此确认与后生成文本同序。具体步骤及重跑限制见本实验 README。

方法和证据限制见[向量数据库怎么测才可比](../../docs/zh/retrieval/vector-search/向量数据库怎么测才可比.md)。历史排错笔记和三份只剩跳转的报告已删除，里面的存储倍数不能再当结论。
