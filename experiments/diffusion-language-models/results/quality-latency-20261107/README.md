# DGX Spark 上的短答案质量与生成时间对照

[English](README.en.md) · 2026-11-07

同一台设备上，四个模型如何回答同一组短问题？这组测试同时记录答案和生成时间，帮助理解速度数字背后的实际输出。它只有 8 道简单算术与字符串题，每题重复 3 次，属于小样本诊断，不能代表模型综合能力。

| 模型 | 严格匹配 | 忽略空白后匹配 | 生成时间中位数 |
| --- | ---: | ---: | ---: |
| Fast-dLLM v2 1.5B | 15/24 | 18/24 | 0.082 s |
| Qwen2.5 1.5B Instruct | 15/24 | 18/24 | 0.061 s |
| LLaDA-MoE 7B-A1B Instruct | 18/24 | 18/24 | 18.432 s |
| OLMoE 1B-7B Instruct | 3/24 | 3/24 | 0.709 s |

3 次重复使用同一题目，并不是 24 道独立题。严格匹配忽略大小写和首尾空白；忽略全部空白的评分是在查看结果后追加的敏感性分析，不提取句中答案。评分反映对指定输出格式的遵循情况，并非语义正确率。例如，Fast-dLLM 和 Qwen 的 `2, 5, 9` 在严格规则下因空格判错；OLMoE 的部分回答虽然包含正确答案，但附带说明，也被严格规则判错；它对 3.8 与 3.12 的比较回答则明确错误。标准答案与问题见 [tasks.json](tasks.json)，每次输出和评分见 [results.json](results.json) 和 [per-run.csv](per-run.csv)。

## 如何理解时间

四个模型在 NVIDIA GB10 上各以独立进程串行运行，使用 BF16，预热 2 次，每题重复 3 次，输出预算为 128 个模型 token。计时覆盖同步后的生成过程，不包括分词与文本解码，也不是首 token 延迟。表中的中位数涵盖该模型的全部 24 次生成。

LLaDA 配置为 128 步、生成长度 128、块长 32，记录的每次返回长度都是 128 个 token；其他模型多数回答只返回几个 token，且可能遇到结束符后停止。Fast-dLLM 使用块大小 32、小块大小 8、阈值 0.9、关闭块缓存。模型训练、tokenizer、参数规模、推理实现、缓存和解码策略均不同，不能将结果当成等长度、等质量的速度比较，更不能把差异归因于扩散或自回归架构本身。

运行环境为 PyTorch 2.14.0+cu130、Transformers 4.57.3。各阶段退出码均为 0；运行时监控到的最低系统可用内存依次为 89.154、89.083、76.866、77.710 GiB。保留既有 ComfyUI，运行前队列为空；50 GiB 可用内存保护未触发。revision 是运行时传入的标识，并非本次对权重内容的独立校验。

## 复算与复现

在本目录执行 `python recompute.py` 可从原始回答重新核对标准答案、逐题严格匹配、空白容忍结果和生成时间中位数。复现生成过程请参考上级目录的 `scripts/quality_tasks.json`、`scripts/benchmark.py`、`scripts/benchmark-llada-moe.py` 和 `docs/质量与延迟对照方案.md`；实际模型文件和具体版本需要另行准备。重复运行的速度与答案可能不同。本次未评估长回答、端到端服务延迟或多次运行的跨时间稳定性。
