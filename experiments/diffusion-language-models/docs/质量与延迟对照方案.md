# 扩散与自回归模型：质量和延迟对照方案

已有速度记录的答案长度、正确性和实现不同，不能直接当作等质量加速比。本方案针对相同的八道短答案任务，对每个模型报告逐题答案、精确匹配率和生成耗时分布。任务只覆盖简单算术与字符串处理，分数不是综合模型能力，也不是人工评审。

## 配置与步骤

四个候选为 Fast-dLLM v2 1.5B、Qwen2.5 1.5B、LLaDA-MoE 7B-A1B 和 OLMoE 1B-7B。模型、tokenizer、训练、推理引擎、缓存和解码机制不同；即便同设备、同精度和任务，结果也是**具体模型与实现的端到端对照**，不是扩散架构的因果效应。两组参数规模只是近似，不能由参数量推定质量或计算量相同。

各模型独立进程使用 BF16、同一设备，预热 2 次，逐题重复 3 次，输出预算均为 128 个模型 token；不同 tokenizer 的 128 token 并非相同字节或内容量，应检查实际答案、输出 token 和字节数。尽可能保持设备空闲，记录模型文件 revision、版本及引擎参数；结果里的设备标签只是运行时上报，评分脚本无法独立验证实际硬件或采样期间设备状态；脚本的 revision 仅为用户提供的记录，不验证权重。重启并更换模型顺序可评估时间漂移。生成计时在 GPU 同步后测 `generate` 或固定步数过程，不包括分词与文本解码；它不是首 token 延迟。若要做真正的端到端比较需另加客户端计时。

扩散固定步数可能在 EOS 后继续计算；自回归模型可能更早停止。不要强行把两者每 token 速度作为等长、等质量指标。以完整回答的耗时和逐题正确率为主，检查截断、EOS、残留 mask；质量不足或输出格式不符合时不能宣称相同质量。八道题是小样本探索，还需增加公开许可的数据、人工质量评估与更大样本。

## 运行

按 README 准备对应环境与本地模型。以下变量由操作者指定，各模型一个独立进程；输出路径必须不存在：

```bash
TASKS=scripts/quality_tasks.json
python scripts/benchmark.py --tasks "$TASKS" --model "$FAST_MODEL" --kind diffusion --revision "$FAST_REV" --warmups 2 --repeats 3 --max-new-tokens 128 --output /tmp/quality-fast.json
python scripts/benchmark.py --tasks "$TASKS" --model "$QWEN_MODEL" --kind autoregressive --revision "$QWEN_REV" --warmups 2 --repeats 3 --max-new-tokens 128 --output /tmp/quality-qwen.json
python scripts/benchmark-llada-moe.py --tasks "$TASKS" --model "$LLADA_MODEL" --revision "$LLADA_REV" --warmups 2 --repeats 3 --steps 128 --gen-length 128 --block-length 32 --output /tmp/quality-llada.json
python scripts/benchmark.py --tasks "$TASKS" --model "$OLMOE_MODEL" --kind autoregressive --revision "$OLMOE_REV" --warmups 2 --repeats 3 --max-new-tokens 128 --output /tmp/quality-olmoe.json
python scripts/score_quality_latency.py --tasks "$TASKS" --runs /tmp/quality-fast.json /tmp/quality-qwen.json /tmp/quality-llada.json /tmp/quality-olmoe.json --out /tmp/quality-summary.json
```

评分脚本仅做去首尾空白、不区分大小写的精确匹配，不执行模型生成的代码；拒绝任务、重复数、预算、设备、精度或预热次数不一致的输入。生成答案如果正确但包含解释或标点，也会被判错，因此需查逐题输出。中位耗时覆盖相同题集的全部重复，不能证明模型在同等质量下的性能；每次只报告观察值及限制。本方案与脚本当前尚未进行 GPU 实测，不产生新的性能结论。
