# 分词器的组成环节与调优杠杆

> 实证日期 2026-09-06 · 环境 pkm-hub-runtime（jieba 0.42.1，MIT）· 脚本 `scripts/probe_jieba_tokenizer.py` · 源码 `jieba/__init__.py`、`jieba/finalseg/__init__.py`

分词器把一句话切成词，由哪几个环节决定，每个环节决定分词的什么性质，分词结果不对时该调哪里。本笔记以 jieba 为样本回答这些问题，jieba 是中文检索里事实标准的分词器，Milvus 把它编译进了二进制。本文做单点纵深拆解，不是性能结论；分词器之间的横向对比见 `docs/主流分词器横向对比.md`，库的横向对照（六个库各接了什么分词器、中文能不能用）见 `docs/六库分词器实现与中文支持.md`，踩坑和根因见 `docs/调试与排错记录.md`。

分词结果由四个可分离的杠杆决定。词典决定分词器认识哪些词，选路决定歧义句子怎么切，隐马尔可夫模型决定词典外的新词能不能被认出，切分模式决定召回粒度。分词不对时，先判断落在哪个杠杆再动手，比逐个参数试更快。

**本篇结论全部从 jieba 0.42.1 源码与实测得出**，脚本见文末「复现」。

## 分词在检索链路里的位置

一段文本进入检索前要经过三层处理：字符过滤器、分词器、词元过滤器。分词器负责中间那层，把连续字符串切成一个个词元。转小写、去停用词、词干提取属于词元过滤器，和分词器相邻但是不同的两层。中文没有空格、也没有词形变化，瓶颈压在分词这一层，词元过滤器对中文几乎无事可做。所以 jieba、icu、lindera 这些选项才会被单独列出来，换成一个英文库，你可能只会看到它们藏在默认流水线里。

## 环节与杠杆

一个词元从句子到进入索引，经过五步：切块、查前缀词典、在所有候选里选概率最大的一条、用隐马尔可夫模型补词典外的词、按检索模式二次切分。前四步决定切出哪些词，第五步决定召回粒度。下面每一步说明它决定什么、拿什么调。

### 切块决定词的边界在哪

分词的第一步用两个正则把句子切成块。`re_han_default` 匹配连续的中日韩字符、字母数字和少数符号，`re_skip_default` 匹配空白。`re_han.split(sentence)` 把句子拆成一段段，连续的非词块再逐字符输出。这一步确立标点和空格是天然边界，后续的词典查询和概率计算只作用在被 `re_han` 命中的字符块内部。它解释了「向量数据库！」末尾的感叹号不会污染分词结果。这一环规则固定，一般不作为调优对象。

### 前缀词典加选路决定歧义怎么切，是最常用的杠杆

词典被读成两样东西：词到词频的映射 `FREQ`，和词频总和 `total`。读词典的函数 `gen_pfdict` 除了登记「向量数据库」这个词的词频，还会把它的每个前缀「向」「向量」「向量数」都塞进 `FREQ`，前缀词频记为 0，等于把一本扁平词典变成可用普通字典查询的前缀树。

`get_DAG` 从每个位置出发向后延长候选，枚举所有词典认可的切法。实测句子「向量数据库的索引构建」的 DAG 里，起点「数」连向「数、数据、数据库」三个终点。`calc` 用动态规划从右往左扫，为每个位置取 `log(词频) - log(total) + 下一位得分` 的最大值，把多候选收敛成唯一路径，本质是在最大化这句话的词频条件概率。实测这句被切成「向量、数据库、的、索引、构建」。

这一环是调分词最常用的杠杆。想让「向量数据库」被当作一个整体、想让某个领域词稳定成词，都调这里。具体调法见下文「词典干预」。

### 隐马尔可夫模型决定词典外的新词，但调它成本高

收敛后的路径里，长度为 1 且不在词典里的字会被交给 `finalseg.cut` 用隐马尔可夫模型重切。模型用 B、M、E、S 四个状态表示词里的开始、中间、结束和单字成词，参数是 `prob_start`、`prob_trans`、`prob_emit` 三张表，发射概率表 `prob_emit` 最大，约 3.5 万行，解码用维特比算法。实测生僻组合「砼浇筑燊淼」被切成「砼、浇筑、燊、淼」，其中「浇筑」是模型认出的成词，其余三个单字没能成词。新词、生僻词、网络用语的分词效果由这一环决定。它要动模型参数，成本高于调词典，通常留到调词典无效时再碰。

### 切分模式决定召回粒度

同一句话有四种切法，差异在要不要做选路、要不要二次切分。精确模式走完前四步，是默认行为，输出最符合语言习惯。无 HMM 模式跳过隐马尔可夫模型，纯按词典加概率切，连续单字符英文会被合并。全模式只输出 DAG 里所有候选，不选路，吐出重叠切法。搜索引擎模式在精确模式之上，把长度超过 2 的词再按二字、三字滑窗切，且只保留词典里存在的片段，用切细换来召回。

实测「向量数据库的索引构建」四种模式输出如下，搜索引擎模式比精确模式多出「数据」「据库」，因为「数据库」被二次切细了。

| 模式 | 输出 | 调它解决什么 |
|---|---|---|
| 精确（默认） | 向量、数据库、的、索引、构建 | 常规分词 |
| 无 HMM | 向量、数据库、的、索引、构建 | 纯词典、可复现 |
| 全模式 | 向量、数据、数据库、据库、的、索引、构建 | 穷尽候选 |
| 搜索引擎 | 向量、数据、据库、数据库、的、索引、构建 | 提高召回 |

带位置的切分 `tokenize` 在搜索引擎模式下给出每个词元的起止下标，「数据库」在原串 2 到 5，「数据」在 2 到 4，「据库」在 3 到 5，起始位置不同，是滑窗重叠切分的直接体现。Milvus 的 jieba 用 `mode` 参数在这几种之间选，`search` 对应搜索引擎模式，`exact` 对应精确模式。

## 词典干预是最常用的调法

jieba 允许运行时改词典。`add_word` 往 `FREQ` 写入词和词频并补上前缀节点，`del_word` 把词频置 0，`suggest_freq` 按期望的切法反推一个能压过原有路径的词频。想让「向量数据库」赢过「向量加数据库」这条路径，就给它加进词典或调高词频。这也是 Milvus 里自定义词典、用户词典的底层机制。实测 `suggest_freq('向量数据库')` 给出的建议词频是 1，因为该词整体不在词典里，按各组成部分词频之积反推回来的值极小，实际用时要按语料再放大。

## 与 Milvus 内嵌版的关系

Milvus 的 jieba 是 Rust 移植版 `jieba_rs`，算法与 Python 版同源，都是前缀词典加 DAG 加最大概率加隐马尔可夫模型这一套。它默认 `mode=search`、`hmm=true`，词典 `dict.txt.big` 通过 `include_str!` 编译进二进制。这套 Rust 实现与 Milvus 的绑定关系在 `docs/六库分词器实现与中文支持.md` 里已实测，本文不重复登记。

## 复现

```bash
cd experiments/test_vector_db_bench
./.venv/Scripts/python.exe scripts/probe_jieba_tokenizer.py
```

脚本打印词典规模、单句 DAG、四种切分输出、隐马尔可夫未登录词结果、词典干预词频。注意本机 jieba 包与 `dict.txt` 装在 pkm-hub-runtime 环境（实验 venv 导入同一份包），词典规模和加载耗时会随环境与缓存状态变化。
