## 这个文档是干嘛的

存档本次基准中六库分词层的版本绑定事实：各库的分词实现源码路径、可选分词器清单、中文实测表。**分词器分类、jieba 的四个杠杆、中文失效的机制解释、选型结论已迁往配套知识库**（《中文分词与 BM25 的工程约束》），本文不重复通用论述，只留换版本后需要核对的实测证据。逐库中文能不能用、为什么，看知识库那篇。

## 分词器实现对照

| 库 | 分词实现 | 可选分词器 | 中文能力 |
|---|---|---|---|
| Milvus 3.0.0 | tantivy 的 C++ 绑定 | `jieba` `icu` `lindera` `language_identifier` `standard` `whitespace` `ngram` `class` `blank` `punct` `camel` | **原生 jieba，可自动识别语言** |
| LanceDB 0.38.0 | lance 的 Rust 实现 | `simple`(默认) `raw` `whitespace` `ngram` `icu` `icu/split`，外加 model-backed 的 `jieba/*` `lindera/*` | 换 `icu`/`ngram` 可用，jieba 需外挂词典 |
| SurrealDB 3.2.4 | 自研，analyzer 需 `DEFINE` | `Tokenizer` 只有 `Blank` `Camel` `Class` `Punct` | 无 |
| Qdrant 1.19.0 | `BasicTokenizer` = Rust `split_whitespace()` | 无额外选项 | 无 |
| ChromaDB 1.5.9 | `Bm25Tokenizer` = 正则去符号 + 空白切 + snowballstemmer | 无 | 无 |
| sqlite-vec 0.1.9 | 无全文检索 | 宿主 SQLite 可另建 FTS5 | 取决于宿主 |

## 逐库实现（源码位置）

### Milvus：唯一把中文分词编进二进制的

分词器在 C++ 层，路径 `internal/core/thirdparty/tantivy/tantivy-binding/src/analyzer/tokenizers/`，含 `jieba_tokenizer.rs`、`icu_tokneizer.rs`、`lindera_tokenizer.rs`、`lang_ident_tokenizer.rs`、`ngram_tokenizer_with_chars.rs`、`char_group_tokenizer.rs`、`thai_tokenizer.rs` 共七个实现。

jieba 用 `jieba_rs`，默认 `mode=search`、`hmm=true`，内置扩展词典 `dict.txt.big`（`include_str!` 编译进二进制）。`language_identifier` 源码在 `lang_ident_tokenizer.rs`，语言识别库可选 whatlang 或 lingua，映射表里 `"Chinese": "jieba"`、`"Mandarin": "jieba"` 硬编码，识别不出落回 `default`。一个已踩的坑：`analyzers` 映射里放 `"mode"` 会被拒（`unknown analyzer option key: mode`），要调 mode 得直接在主 tokenizer 里用 jieba。

### LanceDB：能力全，但要自己选对

分词器在 `rust/lance-index/src/scalar/inverted/tokenizer/`，除 `tokenizer.rs` 外有 `jieba.rs` 和 `lindera.rs`。Python 侧通过 `create_fts_index()` 的 `base_tokenizer` 暴露，默认 `simple`（tantivy SimpleTokenizer，中文无效）。`icu`/`icu/split` 走 `icu_segmenter::WordSegmenter`（UAX#29，中文按单字切）；`jieba/default` 这类 model-backed 需把词典模型放到 `~/.lance/language_models`。

### SurrealDB：四种 tokenizer，都不是为无空格语言设计的

`Tokenizer` 枚举定义在 `surrealdb/core/src/expr/tokenizer.rs`，只有 `Blank` `Camel` `Class` `Punct` 四个值。中文文本在这些规则下都是连续的同类别字符，没有任何切点。`Filter` 枚举的 Snowball 支持 19 种语言，全是拼音文字，无中文。

### Qdrant：源码注释自己承认只是起步用

`lib/bm25/src/basic_tokenizer.rs` 模块注释写明面向 quick-start 与测试，生产用户应自带更丰富的流水线。实现是 `input.split_whitespace()` 加可选小写化，token_id 用 Murmur3 32 位哈希取绝对值。`Bm25Config` 字段完整（k/b/avg_len/tokenizer/language/lowercase/stopwords/stemmer/min_token_len），但底层只有 whitespace 一种实现。

### ChromaDB：为英文设计的完整流水线，中文全部失效

实现在 `chromadb/utils/embedding_functions/schemas/bm25_tokenizer.py`，`tokenize()` 四步：正则去符号（`[^\w\s]+`）、按空白切、过滤英文停用词（约 130 个）、snowballstemmer 词干提取。前三步对中文无效。依赖 `snowballstemmer` 和 `mmh3`，缺任何一个在 EF 构造时抛 ValueError。

## 中文实测

语料 4 条中文句子（向量数据库、索引构建时间、天气散步、全文检索），查询「向量数据库的索引构建」，doc0 为语义相关文档。

| 库 | 配置 | 命中结果（文档下标, BM25 分） |
|---|---|---|
| Milvus | 默认无 analyzer | 空 |
| Milvus | `{"tokenizer":{"type":"jieba","mode":"search"}}` | doc0 **4.62**、doc1 4.01、doc2 0.70 |
| Milvus | `{"tokenizer":{"type":"jieba","mode":"exact"}}` | doc1 3.82、doc0 2.18、doc2 0.72 |
| Milvus | `{"tokenizer":{"type":"icu"}}` | doc1 5.03、doc0 3.36、doc2 0.69 |
| Milvus | `language_identifier`（lingua + Chinese→jieba） | 中文查询 doc1 4.34、doc0 4.25；英文查询 doc3 4.25 |
| LanceDB | `simple`（默认） | 空 |
| LanceDB | `icu` | doc1、doc0、doc2 |
| LanceDB | `icu/split` | doc1、doc0、doc2 |
| LanceDB | `ngram` | doc0、doc1 |
| LanceDB | `raw` | 空 |
| SurrealDB | `punct` / `class` / `blank` | 全空 |
| ChromaDB | `ChromaBm25EmbeddingFunction` | 全 4 条返回，距离 0.815/0.922/1.004/1.115 |

三个值得注意的细节：jieba 的分数尾部衰减快（无关文档压到 0.70），icu 按单字切会把无关 doc2 带进结果；jieba search 与 exact 的排序不同（search 模式 doc0 第一，exact 模式 doc1 第一），差异来自长词二次切分改变了词项权重分布；Milvus 的 language_identifier 在中英混合语料上路由正确，中文查询只召回中文文档、英文查询只召回英文文档，六个库里唯一。

## 复现

```bash
cd experiments/test_vector_db_bench
./.venv/Scripts/python.exe scripts/probe_chinese_tokenizer.py
```

脚本覆盖 Milvus 四种 analyzer 配置、LanceDB 五种 `base_tokenizer`、SurrealDB 三种 tokenizer、ChromaDB 一种。需要 Milvus（19530）和 SurrealDB（8000）在运行。jieba 单点纵深实测（四杠杆）见 `scripts/probe_jieba_tokenizer.py`。
